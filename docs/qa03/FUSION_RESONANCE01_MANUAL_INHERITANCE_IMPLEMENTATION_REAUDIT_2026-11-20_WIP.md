Default-branch code search found no manual inheritance implementation; this is not proof about all other branches. Current status is a source-mapped design, not a tested playable feature.

The public PS2 mod [teolicht505/-P4-Manual-Skill-Inheritance](https://github.com/teolicht505/-P4-Manual-Skill-Inheritance) uses CLPS2C 1.0.5, PS2 executable hooks and code-cave addresses, plus [GPL-3.0 license](https://github.com/teolicht505/-P4-Manual-Skill-Inheritance/blob/main/LICENSE). ## 2. Direct Vanilla algorithm and memory constraints

- [fclFuseRollPersona FUN_00312C60](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/fclCombineMisc.c#L483-L571): scans 8 slots per 0x30-byte parent record; excludes zero, existing result skills and duplicate IDs; computes Vanilla requested count via fclSkillPickCount; caps by 8 - datPersonaCountSkills(result); weighted inheritance using fclSkillWeight, D_00641C40/D_00641E60; inserts chosen into empty slots, returns an 8-bit inherited slot mask. **Critical nuance:** tier count is determined from the unique pool size BEFORE zero-weight skills are excluded from actual rolling. Preserve same tier count and offer only weight-positive eligible skills, then reduce actual choices when insufficient valid skills. No forbidden inheritance or 0xFFFF sentinel.
- [fclSkillPickCount, fclSkillWeight](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/fclCombineMisc.c#L447-L480): verify actual source tables on native branch, no invented P4G rules. Validate edited-save metadata and bounds before reading.
- [yListAllocIndexTable FUN_002E6F00](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_list.c#L2006-L2024) allocates 0x62 bytes: 48 signed-16 IDs + signed-16 count. [fclListAddUnique FUN_002E6F90](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Kosaka/Field/k_fldrc_inferred_002e6f90.c#L38-L56) appends WITHOUT a 48-entry guard. Valid 6 parents * 8 slots = 48 max; reject invalid seventh parent, invalid counts and source corruption. Six-parent full unique pool is a boundary test, not a guarantee all 48 are inheritable.
- [fclCombineFuseSourceRecords FUN_002F9C30](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L4306-L4336): copies 1–6 parent records (0x30 bytes), initializes result, runs Vanilla roll, writes returned inherited skill mask at yListSlotWork(listSlot) + entryIndex + 0x2E4. Manual commit must update result skill slots and this mask atomically exactly once; leave save format unchanged.

## 3. Newly confirmed integration trap: generators run during preview, not only final confirmation

**Do NOT open modal selection inside generic fclCombineFuseSourceRecords or fclFuseRollPersona.**

- [fclCombineHandleGridInput FUN_00321E60](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombineDraw.c#L3138-L3175) loops every available 2-parent candidate, generating preview result records through fclCombineFuseSourceRecords(...,2,...).
- [fclCombineMenuFusion FUN_002ED430](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L2957-L2970) generates triangle preview records inside another roster loop.
- [multi-source creation](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L4057-L4078) generates up to 6-source result after materials held and immediately passes preview record + inheritance mask to fclDrawSetPlacementEx.
- Distinct confirmation modes must be mapped by live input/call traces: normal case 0x2D (y_fclCombine.c L2039+), triangle case 0x46 (L3346+), multi case 0x57 (L4079+). Original [0x60,0x61,0x62 cases are empty](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L4296-L4299). Merely setting those PS2 mod state bytes in the PSP will make no progress without native handler/exit implementation and collision checks.

**Safer independent implementation:** preserve vanilla RNG previews while browsing; on confirmed final transition create a small fusion task-bound session with source Persona IDs + record hashes, result ID, separate base-skill-only scratch record, 2–6 source count, original tier quota, valid unique weight-positive candidates (max 48), chosen IDs (max 8), and proposed inherited mask. Do not let random preview skills leak into the selected result. Capture input only within modal and never double-pass Cross/Circle to the underlying fusion handler. Commit only if session source generation and result still match; write result record and inheritance bitmask as one transaction; resume existing Igor, Social Link bonus, skill level-up and roster/save handling without reroll. Cancel/back, changed parent, HOME, leave-fusion, movie/suspend/restart invalidate the temp session without modifying actual Persona or user save. Validate source/result liveness; no pointer to freed menu work.
