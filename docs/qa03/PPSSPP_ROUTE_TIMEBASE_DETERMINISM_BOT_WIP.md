# QA03 — Q01 bot route timebase mismatch: absolute PSP clock vs replay-local timeline

**2026-11-19 source-only**. Current game runtime perf06 commit `29b0fcfdec70222a4052099b67fb4a11e8d8aff4`; no source edit, emulator execution, script run or new hardware benchmark. T1 logic source proven, T0 actual failure on this installed PPSSPP build.

## Precise source finding

- [P4P `port/pad.c` L31–76](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/pad.c#L31-L76) reads `route.txt` with `S seconds hex` and `A seconds x y`, up to 1,024 entries, assigning **`route[i].at_ms = (unsigned)(at * 1000)`**. There is **no origin timestamp subtraction or replay-start clock** here.
- [`route_apply` L79–101](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/pad.c#L79-L101) uses **`now = sceKernelGetSystemTimeLow() / 1000`**; only route events whose `at_ms <= now` execute. This timer is not anchored to the start of loading a route; it is the emulator/PSP system clock. The function also stops scanning at the first future entry, so the file **must be time-sorted**.
- [`tools/psp_route.py` lines ~13–32](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/tools/psp_route.py#L13-L32) reads the absolute `p4.log` `PADS/STICK` timestamp `t` and outputs **`t - shift`**, where `shift` only contains optionally shortened idle pauses. It **does not subtract the first event time**. This preserves the original session's system-time origin (including time spent at title/menu before recording).
- [`port/pad.c` L112–118](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/pad.c#L112-L118) uses the exact same clock-based route for skipping movie via `p4_route_buttons`, while [L120–165](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/pad.c#L120-L165) merges current physical `sceCtrlPeekBufferPositive`, route inputs, PSPLink injected held/pressed buttons and maps to PS2 active-low bytes.
- [`tools/ppsspp_lab.ps1` L27–38](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/tools/ppsspp_lab.ps1#L27-L38) validates event-line syntax, count and max length, but does **not** normalize or reject nonmonotonic timestamps before writing the route; this could introduce nondeterministic behavior if a route comes from a different boot uptime or edited file.

**Concrete logical counterexample (illustrative, not an observed failure):** A recorded `PADS 418.70 0040` event becomes `S 418.70 0040` without `--cap`; in an otherwise equivalent run where `route_apply` begins when system uptime is 2 seconds, the event will not trigger for approximately another 416.7 seconds. The same route may behave differently when run after a savestate restoration or resume that has different system uptime. `--cap` can shorten later idle waits but does not remove the absolute first timestamp.

**Additional input timing caution:** [`port/pad.c` L148–154](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/pad.c#L148-L154) decrements `p4_pad_reads` per **scePadRead call**, not per rendered frame. Documentation describing this as exactly 'N frames' is potentially false when the game reads the pad more or fewer times between presents. Button assertions for the bot should be based on controlled accepted input edges and game state, not assumed frames.

## Safe bot/input plan, to test after approval

1. **Version route format**: Keep existing absolute-time routes as `v1-abs` for compatibility. New `v2-relative` generated by converter uses `t - t_first + lead_in` or, preferably, routes anchored to an explicit game-state checkpoint. Validate timestamps strictly increasing or nondecreasing and finite, button masks within valid PSP keys and analog X/Y each 0..255. Keep exact source/route hash and initial savestate/room ID.
2. **Runtime input clock** for v2: capture a single `route_start_us` at activation after a known scene/game state and compute wrap-safe `elapsed_ms = (sceKernelGetSystemTimeLow() - route_start_us)/1000` using unsigned arithmetic. Explicitly specify suspend/resume/savestate policy, timeouts, and whether checkpoints use emulated clock vs wall clock. Do not mix v1 absolute events with v2 relative time.
3. **Event order**: monotonic route parser and all buttons released at stop/reset; explicit press+release edges, no spontaneous physical analog contamination. Test old PAD 100ms pulse separately from S held state and A analog position; confirm SELECT+L/R special PS2 L2/R2 mapping. Respect PSP HOME and avoid conflict with user hardware controls.
4. **Host-level stage**: deterministic 5-press menu replay from a clean PPSSPP instance, repeated three times with varied host start delays; compare game state, screen capture and route event confirmations. Then movie skip/title, calendar change, field transition and first short battle. Some PPSSPP WebSocket APIs are available in current upstream docs but must be checked against locally installed version. A long full-story route remains unimplemented.
5. **Do not modify game runtime before P0 GE safety** solely to enhance the bot: add a host route converter validation script/dry-run and a saved report manifest first; any runtime relative clock change must be feature gated and separately T2/T3 verified. Failure packet should include route timebase, route activation source tick and last 100 input events.

## Additional source-proven long-run clock wrap (2026-11-19)

Pinned P4P `port/pad.c` `route_apply` uses `sceKernelGetSystemTimeLow()/1000`, and exact documented toolchain [PSPSDK `src/user/pspthreadman.h` L1588–1595](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/user/pspthreadman.h#L1588-L1595) states it returns **low 32 bits of system time** (microseconds). Thus wrap after **2^32 µs = 4294.967296s ≈ 71.5828 minutes**, far sooner than a complete Persona 4 playthrough. Once wrapped, `now` drops near zero, so existing held S events may stop applying and events >4294s may never be due. Source-proven vulnerability, **not** a PSP/PPSSPP test run or observed bot crash. The header also declares `SceInt64 sceKernelGetSystemTimeWide(void)`: a native 64-bit base option. Use **both** a wide/wrap-accumulated monotonic counter AND route-relative checkpoint origin; simply switching to wide time without subtracting the starting time does not fix first-event boot mismatch. Validate suspend/savestate policies and >72-min synthetic/PPSSPP traces before BOT-3. [Detailed follow-up](PERF07_ROTATION_PAK_IO_MIPS_LINKER_BOT_WIP.md).
