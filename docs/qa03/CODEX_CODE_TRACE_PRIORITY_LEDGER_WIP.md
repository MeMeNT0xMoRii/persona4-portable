## Priority aging rule for each “mach weiter” and the hourly research pass

- Start with **highest unresolved safety blocker** and advance its smallest concrete test/mapping; then take **at least one item from a different category**, so UI/quality/gameplay/audio/bot don't starve.
- Across consecutive runs cycle category **[stability → render quality → UI → performance → gameplay/fusion/mods → audio/video/storage → QA bot/builder]**; keep **P0 safety always visible**, but avoid doing the same analysis without new evidence. Assign OPEN → SOURCE MAPPED → REPRO READY → T2 → T3 → INTEGRATED only with matching evidence.
- Do not confuse **automatic hourly research/notes** with an unattended emulator bot; no game has been autonomously finished.
- Every result: exact file/link/line/version; why user cares; counter-hypothesis; first test in PPSSPP; real Go test; performance/memory risk; repository doc commit and handoff last. If no new source, say which precise access/proof is missing and do not create an empty commit.
