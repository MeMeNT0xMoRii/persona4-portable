## 2. NEW: three independent coordinate pipelines, one visible widget

**Radial geometry**: `shdDrawRadialFan` vertices are world/source screen **float** coords `(86,346)+r*(sin,cos)`, **not derived from `glyphs` UI sprite origin**. **Glyphs/text/selected cursor**: `btlSelectionDrawCommands` sets `btlUiSetOrigin(glyphs, origin[0]-10, origin[1]+28)` and draws row sprite 9,8+i at local `x=52, y=259+15*i -1`, selected sprite at local `x=33,y=258+15*selected`. Actual [`btlUiSetOrigin FUN_002012D0` L329–336 and `btlUiDrawSpriteEntry FUN_00201410` L370–414](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Battle/btlEffect_inferred_00200cb0.c#L329-L414) **truncate the sprite origin floats to s32**, then add local x/y; selected sprite's `factorX/Y`, size/animation/mask are separate. A fractional global shift to 1/3 source pixel may be **discarded by sprite-origin conversion**, while raw fan and rotated strip preserve float values; avoid claiming subpixel-perfect alignment until real resolved sprite bounds.

**Black selected strip**: [`btlPanelDrawStrip FUN_00204DC0` L1304–1389](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Battle/btlEffect_inferred_00202c60.c#L1304-L1389) builds **direct four-vertex float geometry** around `x=inputX+97` and `y=inputY+312+15*(index-3)` with halfwidth=86+64=150, height half8, rotation `angle` and conditional extension; it is NOT a `glyphs` origin-relative sprite. Within the selected-command branch `btlPanelDrawStrip(3,-10,((selected-3)*15+28),110,0,0)`, its center source **(87,295+15*selected)**, native **x=65.25, y=179.1071+9.1071*selected** before any later animation/clip. Text rows have source pitch15→native9.1071 but are under a distinct `(s32)(origin+offset)` base and local `y=258+15*i`. **Do not mislabel stripe Y as menu title Y or assume all draws have one shared `btlUiSetOrigin`.**
**Mode hints**: original same source function branches to `btlPanelDrawExtendedStrip`, restores `btlUiSetOrigin(glyphs,origin[0],origin[1])` before some hint sprites and changes back for later hint draws. A blanket edit to shared `offsetY` will move these hints as well; test fight ATTACK/RUSH/Persona/items, target/command transition, no command modal, and all 8 selection rows. **Scoped patch:** local three fan args+center under one test flag, then separately measured text & stripe correction (coordinated only after same-state video); do not adjust global 2D, `btlUiSetOrigin` callee, `btlPanelDrawStrip` or other fan callers.

## 3. NEW: per-frame display-list budget and UI-state-cache impact

- Frozen [`port/rwsky.c` `typedef GuVertex` L2489–2492](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L2489-L2492): `GuVertex={float u,v;uint colour;float x,y,z}` **24 bytes** on intended 32-bit PSP ABI. [`draw_body` L3403–3558](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L3403-L3558) allocates **`sceGuGetMemory(count*sizeof *out)`** before `sceGuDrawArray`. With fan count50 that is **1,200 bytes of embedded vertex data** per fan, **3,600 bytes** for all three.
- Frozen [`p4_list_cached=1` and list-cache init L677–711](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L677-L711); [`__wrap_sceGuGetMemory` L1904–1918](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1904-L1918) prepends **8 bytes** of BASE/JUMP to the output vertex memory in cached or gate-closed mode. Therefore **3×(50×24+8)=3,624 bytes =906 32-bit words, ~1.3824%** of a **65,536-word per-bank capacity** are implied by the *three active full-resolution fan vertex-memory allocations alone* in a normal cached-list non-skipped path, *excluding* `sceGuDrawArray`, state setup, scissor, cache/wait calls and other UI/game objects. This is **source-derived minimum list usage**, NOT a measured full wheel draw cost or confirmed limit overflow; conditional if an effect/mask policy skips those draws.
- `p4_ui_state_cache=1` [L1869–1874](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1869-L1874), but [`ui_state_eligible` L3392–3401](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L3392-L3401) **only allows `prim==4` ordinary 4-vertex quads**; radial `prim==5` **cannot** reuse that UI state fast path. Therefore **no extra fans and no global fan tessellation increase** in the first geometry trial. The calculation implies unchanged vertex/list contribution if the same 3×50 fans are retained; no confirmed FPS improvement or cost regression.
- SEC-01 hard pre-write bounds and correct bank retirement remain **P0**, because `sceGuGetMemory` currently has no robust per-writer capacity guard. Ensure final per-bank word headroom and no 250ms/1s unsafe rollover before adding any test draw instrumentation.
