# SEC-01s — signed sceGuGetMemory size validation before GE pointer arithmetic (2026-11-20 22:00 CET)

**Priority:** SEC-01 / P0. **Evidence:** T1 static source; runtime exploit/failure T0. **Frozen source:** `29b0fcfdec70222a4052099b67fb4a11e8d8aff4`, [`port/rwsky.c::__wrap_sceGuGetMemory` L1901–1920](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1901-L1920). [Perf06 control](PERF06_RUNTIME_BASELINE_FORENSICS_WIP.md): pipelining, cached GE lists, skin strips, mips ON; regular vs diagnostic artifacts distinct.

**Distinct exact source observation:** The wrapper accepts a **signed int** `size`. In its guarded/cached branch it executes `size = (size + 3) & ~3` and computes `(unsigned)at + size + 8`, writing `at[0]` and `at[1]` without validating nonnegative size, checked addition, command-tail space, list base/end or GE bank ownership. The unguarded branch delegates to `__real_sceGuGetMemory(size)`, which must be audited independently. **In C, `size + 3` has signed-overflow UB for values greater than INT_MAX-3**; a negative size also cannot be accepted as a valid vertex reservation without an explicit caller contract. This is a *separate input-domain problem* in addition to SEC-01n's known 8-byte list boundary and SEC-01o's unchecked caller pointer.

**Hypothesis/falsifier:** An invalid or corrupted signed size could overflow arithmetic or move the current GE pointer backward/outside its bank. This is **not** evidence that any real perf06 call passes such a value. Falsify by static census of every callsite, proving bounded nonnegative size, plus a host unit test covering 0, 1, 3, 4, 480-wide striped clear, INT_MAX-2, INT_MAX and -1, and a bounded GE trace proving no out-of-range writes. Do not feed malicious sizes to a physical PSP Go.

A NULL-on-failure return is **not** safe for current callers (SEC-01o); fail closed with an explicit frame-abort/diagnostic path that cannot dereference the failed allocation, cannot submit a partially corrupted list, and cannot reuse a still-owned bank. No blind increase to 128Kiwords without RAM/GE accounting.
