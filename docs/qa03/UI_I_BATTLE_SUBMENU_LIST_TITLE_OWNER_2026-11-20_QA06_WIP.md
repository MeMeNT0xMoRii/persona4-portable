## Newly pinned code owner — independent header vs list rows

Exact original [`src/Battle/btlEffect_inferred_00202c60.c::btlSelectionDrawList FUN_00205FF0` L1783–2055](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Battle/btlEffect_inferred_00202c60.c#L1783-L2055):

- **Heading/title** L1916–1931: reads `((BtlPanelWork *)state)->titleFrame`, computes `clamped = 1 - (2*t - t*t)` for clamped `t=titleFrame/10`, then draws **sprite segment `0x29`** with color (0x1B,0x1B,0x1B) and `alpha=(1-clamped)*255`, at **source `x=410.0f+offsetX - clamped*200.0f`, `y=113.0f+offsetY`**. In settled state `titleFrame>=10`, `clamped=0`, the base source x=410/y=113 remains; during transition x changes by as much as 200 source units and fades in/out. That is **one title record/transition**, not the positions of rows.
- **Rows and highlight** L1933–1966: dynamic rows via callback `drawSelection(state,slot, rowX=97.0f+offsetX, rowY=145.0f+offsetY+31.0f*row, opacity=255, selected,...)`, with selection stripe at `x=0x1DF+offsetX` and **source y=143+31*row+selectedOffsetY**. The list has its own `listFrame` slide animation and `clipFrame` scissor/mask at L1827–1905. Unbounded shifting of `offsetX`, `offsetY`, global 2D projector or `btlSelectionDrawList` changes these rows, header, scrollbar and prompts together and would be inappropriate.
- **Scrollbar** L2035–2051 draws `0x2D,0x2E,0x2F` at source x461/463 with own ratio/page, not part of `0x29`. **List text** callback `btlPanelDrawListRow FUN_00205E00` L1756–1778 draws marker sprites at x48/71/270 relative to row and `itfMesWindowDrawEntry` separately.
- **Callers/variants:** Skill L2824 `btlSelectionDrawList(...,btlPanelDrawSkillEntry)`, Item L2998 callback `btlPanelDrawEntry`, Tactics/other selection `btlSelectionDrawCurrentLabel FUN_00209FA0` L3325 callback `btlPanelDrawListRow`. **Shared title owner** `FUN_00205FF0` makes a narrowly isolated test useful, but a single edit will affect Skill, Item, Persona and Tactics, so all need negative controls.

Frozen PSP `port/rwsky.c` uses `target_sx=0.75`, `target_sy=272/448≈0.60714286`; the **nominal title *anchor input*** in settled state (ignoring `offsetX/Y`, sprite record origin/pivot, scaling, tween, scissor) is **`(307.5,68.6071)` native**. **This is NOT the text's visible left edge or a desired final UI coordinate.** Likewise nominal row input x97→72.75 and first row y145→88.0 native; screenshots show glyphs elsewhere because sprite local offsets/pivots and parent state are applied. Do not infer a source delta by subtracting visible pixels from nominal anchor.
