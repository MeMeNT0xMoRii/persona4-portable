## T1 performance triage and diagnostic traps

- **CPU/GE pipeline and frameskip.** [`rwsky.c` L450–471](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L450-L471) defaults `p4_pipeline=1` except `P4_GE_DUMP` and `p4_frameskip=1` / max 2. Rendered frame cadence and simulation cadence need separate reporting; frameskip can preserve game speed while reducing presented frames.
- **GE-timer cannot benchmark stock pipeline.** [`p4_exp_ge_time` L2109–2174](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L2109-L2174) forces GE dry/wait before and after timed pieces; it refuses to run with `p4_pipeline=1` and notes a historic hang when turned on mid-pipeline. Its serial mode adds instrumentation overhead and changes throughput. `ge time empty piece` calibration [L10952–10958] matters; GE category times are *not* normal pipelined frame times.
- **Useful existing safer first instrumentation:** `P4_HW_PROFILE` includes `PROF_FRAME`, `PROF_2D`, `PROF_SYNC`, `PROF_SKIN`, `PROF_QEFFECT`, `PROF_QPRIM` and cache-stall counters [`rwsky.c` L45–165](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L45-L165), but requires PSPLINK thread profiler and has section-edge overhead. The normal 128-frame summary [L1637–1667](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1637-L1667) prints `cpu_us`, `ge_wait_us`, `present_us` in a *profile build*. [`tools/psp_hw_debug.py` L30–73](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/tools/psp_hw_debug.py#L30-L73): diagnostic build defines `P4_HW_PROFILE`, `--release --frame-timing` selects `P4_FRAME_TIMING` on XMB, `--ge-dump` gives the special serial GE dump. Verify build flags before trusting logs; **none were run here**.
- **Strong specific performance/quality tradeoff to test:** defaults [`p4_dst_alpha_passes=0, p4_alpha_pixel=0` L893–901](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L893-L901) mean [`draw_body` L3495–3544](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3495-L3544) skips some **destination-alpha blend** passes (`0x52/0x54/0x58`) and some alpha writers under **half a PS2 screen** unless a carve-out applies. The reasons and observed dark-minimap/square artifacts are in source comments. This can lower fill/draw cost **and potentially suppress legitimate VFX**, but is **not proven** to produce the specific Zio/fusion light orbs. No blanket enable: it may reintroduce hard square overlays.
- **Camera-texture / feedback budget:** [`rtt_get` L1201–1273](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1201-L1273) reserves at most four RTT slots in 2 MiB GE eDRAM; with two 32-bit 512×272 framebuffers and 16-bit 512×272 depth, the screen feedback slot lies at `RTT_FULL_BASE`. Default `p4_rtt_scale=0` tries the post-feedback tail then **falls back to half-sized RTT** if full cannot fit; `p4_rtt_scale=1` may collide with feedback and force a separate copy route. [`capture_feedback_vram` / `capture_feedback_half` / `bind_raster_body` L2540–2670](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L2540-L2670) confirms explicit copies and texture-cache synchronization. These are candidates for CPU, bandwidth, GE stalls and quality tradeoffs in scenes using RTT/feedback; **no Junes-specific RTT usage demonstrated**.
- **3D atomic opportunities should be measured, not guessed:** `atomic_render_body` [L10984–11088] records sphere cover/vertex/mesh work; `draw_meshes` [L6232–6270] has replay and persistence caches; `draw_meshes_body` [L6380–6495] already supports UV memoization, per-mesh guards, compact geometry and cache hashing. Check `cover top`, `hwprof mesh/skin/guard`, `rtt passes`, mesh/texture misses, and CPU GE-wait to decide if Junes is CPU transform, overdraw, depth/multipass, state churn or texture traffic. Previous b388 Junes sample remains user-observed ~12/13 instantaneous FPS, **not a new benchmark**.
