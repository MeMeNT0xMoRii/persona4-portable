2. [`flip_main` L647–667](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L647-L667) advances `shown_seq` only after `ge_finished >= flip_seq` and display flip. The GE finish callback [L554–566](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L554-L566) increments `ge_finished`; frame sequence numbers, rather than transient GE list IDs, track completion. Source comments explicitly warn that GE IDs can recycle.
3. [`func_003f79b0` L1499–1533](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1499-L1533) begins a present with `while (shown_seq < ge_queued)`. >250ms: `sceGeListSync`, log GE state and force prior `pipe_last_end` into stall (already separately documented). **>1s: logs "going on", increments `pipe_watchdog_gave_up`, and executes `break` while `shown_seq < ge_queued` can still hold.**
4. **New causal edge:** code then continues [L1585–1616](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1585-L1616): if current frame in progress, `sceGuFinish(); ge_queued++`, publishes `flip_seq`, chooses other framebuffer, `gate_close(ge_queued)`, **unconditionally `pipe_set ^=1; list = list_store[pipe_set]`**. If the old GE list has **not finished** (`ge_finished < its seq`), next frame's [`begin_frame` L2822–2838](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L2822-L2838) calls `sceGuStart(GU_DIRECT, list)` and writes frame commands **into the bank an older live GE list may still reference**. Thus the 1s watchdog can break a two-bank command/vertex-pool lifetime invariant even **when a list never exceeded its 65,536-word capacity**. The GE consumer may be stalled or still active. **Crucial distinction:** `shown_seq` may lag purely because the flip thread has not shown an already completed GPU frame; in that case `ge_finished` can be sufficient and **no live-list overwrite is implied**. Only an unfinished GE frame + premature bank recycle yields this particular hazard. This is **not an observed outcome**.
5. **Second new conditional check:** frozen `begin_frame` [L2828–2833](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L2828-L2833) **ignores the `sceGuStart` return value**, and the two `sceGuFinish` callsites [L1539–1542, L1588–1594](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1588-L1594) **ignore return status** yet increment `ge_queued` on finish. Official pinned [PSPSDK `sceGuStart.c` L14–49](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuStart.c#L14-L49) first points the GU context at caller-provided memory, then calls `sceGeListEnQueue(local_list,local_list,...)`, and **returns a negative enqueue error** if this fails; it does not reset the caller's two-bank memory safety state for a failed start. [`sceGuFinishId.c` L23–59](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuFinishId.c#L23-L59) appends FINISH/END and forwards a potentially negative stall status. Therefore a queue-pressure/error branch could lead to `ge_queued` counter advancing without a valid accepted GE list; **this too has never been observed**. A Saturday instrumentation build should check return values without silently altering default list/context semantics, and never assume normal `sceGuFinish` return is a boolean (normally it is list size).
6. **Observability:** `pipe_watchdog_gave_up` is assigned at L1459 and incremented L1524 but **is not printed elsewhere in the pinned `rwsky.c`**; individual "going on" logs exist, yet no existing per-scene/release aggregate. `list_writebacks`, `pipe_peak_v/i`, FPS median and `timing_bytes` do **not** independently prove both list banks' lifecycle safety. In default EBOOT `P4_FRAME_TIMING` is not proven enabled and the diagnostic `P4_GE_DUMP` forces serial pipeline=0, so use distinct EBOOT/build hashes.

## Deterministic source-level two-bank timeline (model; not executed on PSP)

| Step | `ge_queued` relative | GPU/flip state | What perf06 does |
| --- | --- | --- | --- |
| A | frame N queued on bank 0 | GE for N unfinished; shown <=N-1 | CPU may build frame N+1 on bank 1 behind gate |
| B | present for N+1 | `shown_seq < ge_queued` persists >1s | watchdog breaks while N still unfinished (conditional) |
| C | N+1 finishes CPU submission | GPU still references bank 0 from N | unconditionally bank flip from 1→0 and advances `ge_queued` |
| D | N+2 begins | unfinished N bank 0 potentially still live | `sceGuStart` points GE to **same bank 0**; commands may overwrite live list if backend accepts and CPU writes |
| E (negative control) | N already GE-finished but display flip delayed | `ge_finished >= N` | bank 0 is not live from N; stale display alone does **not** establish list overwrite |

This path is conditional on actual backlog state, not on every slow 12-FPS Junes frame, which is far below the 1-second guard. A real 250ms/1s event is a **diagnostic abnormality**, not a nominal performance optimization trigger.

## Test plan, minimal invasive diagnostic before fix (future authorized build only)

- **Invariant:** a bank/vertex half must not be reused until all GPU work referencing that bank has signaled completion; a pending display flip is stricter (safe conservative fence), not proof of GE still drawing. Before bank rollover: record bank index, list `start/current/hi` words, `ge_queued/ge_finished/shown_seq/flip_seq/gate_seq`, `pipe_last_list/pipe_last_end`, `sceGeListSync`, **return from `sceGuStart` and `sceGuFinish`**, forced-stall count, reason (GE-pending vs flip-delayed). Only log on exceptional >250ms paths and a bounded per-256-frame summary; avoid ~FPS-impacting per-primitive writes/logs.
- **Host-only state-machine test** without PSP code edits: synthetically model (A) normal 0/1 ping-pong, (B) GE unfinished after timeout, (C) GE finished but flip thread delayed, (D) negative GU enqueue return, (E) frame skip with `!in_frame`, (F) serial mode; assert no live-bank write is permitted even on timeout, and that counting accepted GE submissions is not conflated with counter increments. Maintain exact trace table as expected results, not actual PSP timings.
- **Only if reproduced in an approved diagnostic:** design a **fail-closed** safe state, not naïve infinite `sceGeListSync` spin (historical deadlock) or blind 1s continuation. Choices include preserve the in-flight banks, stop accepting new GPU work with watchdog report and orderly reset/exit after safe IO completion; or recover the GE queue/bank **only after positive completion fence**. Do not specify an untested recovery as mandatory. Preserve HOME, save semaphore, full game clock, task progression and audio behavior. Do not fix a replay hang by simply switching `p4_pipeline=0` permanently; perf06's documented pipeline CPU/GE overlap is important.
- **Scene and save cohorts:** genuine fog-heavy battle/reinforcement with normal vs edited **copies** (separate STAB-01), Junes West F009_004 with RTT and School 2F F006_002 as negative control. Hardware A/B requires **regular perf06 A**, separate diagnostic build ID and hash, same camera save, 20s still +10s walk for perf, follow-up native Go p50/p95, and no apparent improvement at the cost of corrupted output or skipped gameplay.
- **Disproof:** If `sceGuStart`/Finish always succeed and every watchdog timeout is display-only with `ge_finished >= prior seq`, the **live-bank overwrite** part is falsified for those traces. If GE hasn't finished but never reaches 1s, this particular 1s continuation path cannot explain that occurrence. GE capacity and cached-stall hazards remain independent.
