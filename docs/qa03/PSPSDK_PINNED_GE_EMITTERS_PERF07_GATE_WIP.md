## Verified SDK command append mechanics (PSPSDK@09f02b88b9f3)

| Source owner | Exact behavior, independent of P4P wrapper | Consequence |
| --- | --- | --- |
| [`src/gu/guInternal.h` L604–618](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/guInternal.h#L604-L618) | `sendCommandi` writes `*(gu_list->current++) = (cmd << 24) | (argument & 0xffffff)` directly. It does not check an end pointer; `sendCommandf` delegates to it. | **Every** SDK GU state call that internally uses `sendCommandi/f` can overrun the caller-provided P4P list even if `sceGuGetMemory` is wrapped. A wrapper-only fix is incomplete. |
| [`src/gu/sceGuGetMemory.c` L13–34](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuGetMemory.c#L13-L34) | Rounds requested size to four-byte alignment, appends two 32-bit BASE/JUMP words, advances current by `size+8`, updates GE stall if no nested context, returns data pointer. No capacity field in `GuDisplayList`. | Matches P4P [`__wrap_sceGuGetMemory` L1903–1918](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1903-L1918) unbounded pointer growth. Caller may write vertices to return without checking NULL. |
| [`src/gu/sceGuDrawArray.c` L20–36](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuDrawArray.c#L20-L36) | Issues optional VTYPE, optional index BASE/IADDR, optional vertex BASE/VADDR and mandatory PRIM; max 6 GE command words for this path, then stall update. | One high-frequency draw helper bypasses any bound check in custom vertex allocator. Need an SDK-aware preflight or a bounded emitter linkage/instrumentation mechanism, not a blind post-draw check. |
| [`src/gu/sceGuTexImage.c` L33–35](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuTexImage.c#L33-L35) | Sends three commands per texture level (address, buffer width, size) via raw `sendCommandi`. | Native P4P `bind_native_mips` also manually writes 3 per level; both raw and SDK paths matter, avoid double counting where one branch replaces other. |
| [`src/gu/sceGuBoneMatrix.c` L23–28](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuBoneMatrix.c#L23-L28) | Sends one BONE_MATRIX_NUMBER plus 12 floating matrix-element commands = 13 total. | Exactly matches P4P `p4_bone_direct=1` L10341–10354 custom fast path; both possible branches emit 13 words without end checks. |
| [`src/gu/sceGuClear.c` L51–93](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuClear.c#L51-L93) | Allocates two or more temporary sprite vertices via `sceGuGetMemory`, then uses `sendCommandi(CLEAR_MODE,...)`, `sceGuDrawArray`, and `sendCommandi(CLEAR_MODE,0)`; unconditionally fills returned vertices. | If a wrapper simply returns NULL on overflow, **sceGuClear immediately dereferences the NULL vertex pointer**. Failure policy must abort/safely complete frame as an **atomic render action**, not skip one allocation. Fast clear can require more vertices. |
| [`src/gu/sceGuStart.c` L18–79](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuStart.c#L18-L79) | Initializes `gu_list` with caller-supplied memory pointer and emits initialization/framebuffer commands; `GuDisplayList` has **only start/current/parent context**, no end/capacity. | P4P must supply a **separate per-bank known end** and account for first-start state. An SDK helper cannot infer a `64*1024` size just from `gu_list`. |
| [`src/gu/sceGuFinishId.c` L20–53](https://github.com/pspdev/pspsdk/blob/09f02b88b9f3/src/gu/sceGuFinishId.c#L20-L53) | GU_DIRECT and GU_SEND append **FINISH, END** two final 32-bit commands; nested GU_CALL emits RET or SIGNAL+END. | **Always preserve room for termination**, including before any overflow bailout and while pipelining. A full command list with no 2-word tail reserve cannot be validly finished. |

Additional existing P4P direct list append sites are catalogued at [`GE_WRITER_CENSUS_AND_REPLAY_PERF_AB_WIP.md`](GE_WRITER_CENSUS_AND_REPLAY_PERF_AB_WIP.md): own wrapper; custom mesh PRIM; mip descriptor chain; GE BASE+CALL; variable-size instance replay memcpy; GE skinned bone; optional persisted-body replay. Both SDK and P4P **share the same `gu_list->current` current pointer**, but **not a capacity field**.

### Converged safety design — no runtime change authorized in this research pass

1. **First discover exact shipped toolchain/libraries** by checking local PSPDEV/PSPSDK source or built archive hashes and ELF link map; documented snapshot is likely but not an EBOOT assertion. Catalog GU symbol calls/indirect SDK helpers actually linked.
2. **Do not try to wrap only `sceGuSendCommandi`**: many SDK functions call internal inlined `sendCommandi` in their own objects; a wrapper around exported `sceGuSendCommandi` does not interpose those inlined stores.
3. Preferred risk-minimizing candidates, for later isolated experiments: (A) **generously sized, memory-headroom-checked lists** with conservative high-water guard+stop before unsafe path and dedicated tail reserve; (B) more invasive bounded emitter at SDK compile/library integration layer for full coverage, coupled to frame-safe abort if overflow. Both need SDK re-link and resource checks. Merely post-checking `sceGuFinish` is too late; merely returning NULL from `sceGuGetMemory` breaks `sceGuClear`. A fake success pointer into scratch memory is unsafe too: SDK will emit associated GE draw commands unless atomic call prevented.
4. Budget **2×65,536×4 = 524,288 bytes existing list BSS**; moving to **2×131,072×4 = 1,048,576 bytes** increases **main RAM by 524,288 bytes**, not VRAM. Separate P4P dynamic CALL ring up to 1,048,576 bytes and mesh cache ~6MiB; check fixed `.p4image`, max contiguous heap and dual pipeline synchronisation. Do not lower original PS2 visual fidelity or disable 3D to conceal overflow.
5. Add **static guard/SDK stress harness** for near-list-end operations: one VTYPE+PRIM draw, 3-command tex level, 13-command bone, FAST_CLEAR scratch and draw, final FINISH+END, variable memcpy CALL replay, nested call context. The harness must verify **no overwrite and valid frame termination** under host/dry-run conditions; do not intentionally trigger corruption on real PSP Go.
6. After T1 SDK audit, use PPSSPP T2 in heavy fog/reinforcement, Apsaras/Fusion, Junes RTT and 16:9 UI + title transitions; measure list **maximum occupancy**, bank and tail reserve, CPU/GE and memory. Real PSP Go T3 required before interpreting stable 20→30 FPS or merging renderer experiments.
