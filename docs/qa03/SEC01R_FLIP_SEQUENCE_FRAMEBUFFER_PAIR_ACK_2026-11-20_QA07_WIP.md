## Actual source-level inter-thread contract

1. `flip_main` [L650–663](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L650-L663) reads global `unsigned seq=flip_seq;`, checks `seq!=shown_seq && (int)(ge_finished-seq)>=0`, **then separately reads `void *fb=flip_fb;`**, waits vblank, issues `sceDisplaySetFrameBuf(...fb...)`. On successful API result it calls `fps_presented()`; **whether success OR error, it executes `shown_seq=seq` and `flip_signal(FLIP_SHOWN)`**. `flip_seq` and `flip_fb` are independent volatile fields, not a structurally synchronized `(seq,fb,GE-status)` snapshot. This does not *by itself* prove a physical concurrent race, but the code has no matching lock/atomic pair.
2. Producer `func_003f79b0` [L1498–1527](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1498-L1527) **normally does not publish another frame** while `shown_seq < ge_queued`. That protects the pair in normal operation. At >1 s timeout the waiter breaks **without confirmed display or GE retirement** (previous SEC-01Q); after it has built next frame, producer [L1587–1600](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1587-L1600) writes `flip_fb=draw_buffer` and only **later** writes `flip_seq=ge_queued`. The two writes do not form an atomic published pair and the pending old `flip_main` may be interleaved.
3. `gate_poll` [L1890–1899](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1890-L1899) opens closed GE stall if **`shown_seq>=gate_seq`**, regardless of whether the matching `sceDisplaySetFrameBuf` returned an error. Consequently a **hypothetical failed display API call** moves the `shown_seq` progress marker and may authorize rendering into a framebuffer that remains on screen, while `fps_presented` correctly does **NOT** count it. It also conceals a display/API failure from purely `shown_seq`-based Diag-Lite logic. **API actual failures on perf06 T0**; never assert this is the cause of a user's live bug.

## Minimal valid torn-pair interleaving (conditional, synthetic H0)

| Time | GE/display state | Consumer `flip_main` | Producer after 1s watchdog |
|---|---|---|---|
| A | `ge_queued=7`, `ge_finished=7`, `shown_seq=6`; pending frame7 in buffer A0 | reads `seq=flip_seq=7`; eligibility succeeds | waits because shown6 != queued7 |
| B | frame7 still not display-ACKed | temporarily descheduled before reading `flip_fb` | timer expires; producer **allowed to continue** with frame8 |
| C | frame8 references buffer A1, may still be GE-stalled | — | writes **`flip_fb=A1` then `flip_seq=8`** |
| D | GE for seq7 finished; GE for seq8 MAY be unfinished | consumer reads **new `flip_fb=A1`**, keeps **old `seq=7`** | publisher has newer `flip_seq=8` |
| E | display API accepts A1 (possibly not yet rendered) | `shown_seq=7`, accepted counter advances for **wrong framebuffer**, gate for 8 still closed | next consumer waits for GE8 |

This demonstrates a schedule **permitted by the source** when watchdog allows re-publication, not a measured PSP multi-thread execution. Even if original queue/bank retirement were repaired, a naive unchanged global `flip_fb` + `flip_seq` handoff might still accept the wrong framebuffer. **Negative control:** no watchdog timeout (shown6/queued7) blocks the producer, leaving both values consistent. **Second negative control:** `ge_finished<7` blocks the old consumer altogether. This is separate from the earlier **old GE list bank memory overwrite**; this interleaving can pick the wrong framebuffer **even when GE7 itself is finished**, because display acceptance is late.

## Saturday focused diagnostic/repair contract — DO NOT patch immediately

- Label **SEC-01r P0 together with list capacity/retirement**: before first 1s watchdog event, 4 distinct counters `ge_submitted_seq, ge_finished_seq, display_pending_seq, display_accepted_seq`; each has immutable `framebuffer_id + list_bank_id + submitted/finished/ack result + timestamp`. A failed `sceDisplaySetFrameBuf` must NOT silently count as accepted; maintain separate attempted/failure and bounded retry/error state. Do not report accepted FPS from sequence alone.
- Pair `seq + fb + frame bank + GE token` *coherently*. Candidates: a **two-slot per-frame immutable descriptor with explicit generation/retirement**, or a **short synchronized publication/snapshot critical section** after verifying PSP threading/interrupt semantics and state lifetime. **Naive “read `flip_seq` again after `flip_fb`” is insufficient** by itself because producer can write new FB before new seq, and both reads can still see old seq. A seqlock-like protocol needs an **in-progress generation visible before FB write**, proper memory ordering and reader retry; no infinite spin under thread starvation.
- Process actual display API result and do not release a framebuffer to GE merely because a failed display attempt was marked `shown_seq`. Preserve a bounded fallback/abort/diagnostic path so a display failure does not itself cause indefinite idle or unbounded logging. Check `sceDisplaySetFrameBuf` when video path and frame timing also active, but keep movie source owner separate.
- Stress ***host/safe PPSSPP*** interleavings: old seq ready + new fb published, negative display, prior GE unfinished, both buffers/GE banks, watchdog vs no watchdog, vblank-delayed flip, sequence u32 wrap, GE callback delayed, and exit/movies. Capture actual `p4.elf` symbol owner plus a bounded `FLIP_ATTEMPT/FLIP_ACCEPT/FLIP_ERROR/QUEUE_REPUBLISH/OLD_SEQ_NEW_FB` Diag-Lite event; no per-frame disk writes. A naive frame-serial blocking fix may tank accepted p95; **keep 2-bank pipeline on healthy path** and fail closed on only genuine anomalies. Physical PSP Go T3 only after P0 GE safety, under normal gameplay/standby, never deliberate raw memory corruption tests.
- Before attributing existing reinforcement freeze or black-frame bug, demand one real recorded API failure, watchdog counter or mismatched `(seq,fb)` in a T2 run, and later Go T3. No synthetic H0 -> real root cause promotion.
