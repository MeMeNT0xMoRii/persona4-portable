## A. NEW concrete failure precondition: Compendium Register / modified saves (P0 stability)

The original Persona list implementation gives us a materially stronger reproducibility target than generic 'modified-save data may be wrong':

1. [`src/Yajima/y_list.c` `yListSlotRefresh` **FUN_002E4090**, lines 663–735](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_list.c#L663-L735), specifically `case 6` (Register), enumerates *active* roster slots; copies 0x30 bytes of the persona, indexes metadata with **`current.id`**, checks Arcana <0x16, then unconditionally calls `memcpy(&registered, datPersonaCachedRecord(current.id), 0x30)` before comparing current vs registered. There is no explicit **NULL test of the cached-record pointer** in this case.
2. [`src/g_data/g_data.c` **`datPersonaCachedRecord` FUN_0010FCB0**, lines 2699–2712](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/g_data/g_data.c#L2699-L2712) asserts `0 <= personaId < 0x100`, returns a record *only when the cached persona flags include active bit 1*, and **returns NULL otherwise**.
3. [`src/Main/Battle/Data/datPersona.c` lines 700–748](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Main/Battle/Data/datPersona.c#L700-L748) independently checks active roster flags and supplies records by slot. **An active roster Persona with inactive/missing cached Compendium record** is thus a code-demonstrable **invalid-input dereference risk** at Register. An out-of-range `current.id` can also index metadata **before** the range assertion in `datPersonaCachedRecord`. Neither condition proves that this user's five-persona save actually contains it.
4. Historic user hardware symptom: **five-persona complex modified save crashes at Register**, other saves work. Original save and minimal edited save must remain separate controls; minimal Register result **not yet provided**. **Do not claim the game's normal obtained Personas lack cache entries**, change original validation globally, or overwrite user saves.
5. **No-write first test**: using private copies of all three saved data states, print for each active roster slot **slot, id, active bit, Arcana validity, cache-active bit, cached pointer/record availability, `yListRecordsDiffer` applicability, checksum**, and gate access before dereference. Compare failing vs original/minimal. If the invalid cache state is observed, make *one* local experimental fallback: controlled missing-record behavior (either register as new/mark eligible or show safe failure), preserving vanilla semantics, and compare PPSSPP/PSP-Go. **A simple `continue` guard stops the invalid read but may hide an intended Register option**; select semantics only after an original-save comparator. No fix implemented here.

## B. Enemy reinforcement freeze, HOME, save integrity — distinct failure paths

- Historic PSP-Go observation: after a winning battle transition to enemy reinforcement, a held image remains; **HOME still exits**; save was modified and exact perf06 build not reconfirmed. This is **not yet a proven renderer hang or a general game crash**.
- Pinned original [`docs/probe_archive/P022_001ef9c0_body.c`](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/docs/probe_archive/P022_001ef9c0_body.c) traces a distinct enemy genus-1 reinforcement constructor call **retail 0x001AC008 → `func_0019f5f0`** (separate from party and initial encounter), giving an actionable *constructor region*, not the freeze's root cause. [`btlFormationAllocWork` **FUN_001D3D50**](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Battle/btlFormation.c#L1102-L1123) explicitly chooses deferred-loading state (mode 2/flag 8); [`btlFormationSetPlacement` **FUN_001D3E00**](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Battle/btlFormation.c#L1125-L1142) manages deferred resource release/reference. **Which path the failed transition reaches is T0**.
- **Discriminator already available:** P4P [`rwsky.c` lines 1495–1544](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1495-L1544) has a **250-ms GE/pipeline watchdog**, prints queued/finished/shown list counters and GE registers, then logs a 1-second unresolved stall. When the user reproduces freeze, check `TRACE pipeline watchdog` vs **battle actor/formation asset-loading/task checkpoints**. A stalled display with HOME responsive is not enough to convict GE.
- P4P [`port/lifecycle.c` L27–60](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/lifecycle.c#L27-L60) gates new save I/O using a semaphore and checks GE before `sceKernelExitGame`. [`port/memcard.c` L146–207](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/memcard.c#L146-L207) stages save write through `.tmp`, rotates `.bak` and calls `sceIoSync` twice. These are **verified protection mechanisms**, not proof that every HOME/save timing race is eliminated; separately test cold save/load, HOME during idle, HOME after save, repeated saves with hashes, original untouched control.
- For freeze, log **pre-victory, last enemy removal, new formation request ID, actor count/genus, deferred-load status, asset ready state, last game task, frame count and GE watchdog**. Save cohort A untouched original, B minimal, C complex modified. Abort on first reproducible corruption and keep backups. Do NOT change CPU/renderer and save mutation in one build.
