## New STAB-02g findings from this specific status/research pass

Original pinned source chain: `btlEffect.c FUN_001EA2D0` → `btlUnit_inferred_0019e9f0.c FUN_0019EF30` → `btlUnit_inferred_0019d150.c FUN_0019D210` and `btlEffect_inferred_001d6f20.c FUN_001D6F20` + `btlEffect_inferred_001d6a60.c FUN_001D6AD0`. 1 unit 0xA70 + placement 0x18 + fade node 0x24 + pool 0xC8 + 48×0x24 nodes = **4660 request bytes over 52 separate calls**. Initial unit `memset` immediately uses allocator result, so if callback returns NULL the earliest unsafe use is **inside** `btlUnitCreate`, *before* outer child init returns. Original [`src/nmlist.c` L40–75](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/nmlist.c#L40-L75) and [`effBattleOnly.c` L50–60](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Graphics/Effect/effBattleOnly.c#L50-L60) **do** guard NULL results of the same allocator callback with `kAssertFail`. Child `charId*0x58` metadata indexing also lacks local domain check; actual table size unknown. Teardown recursively frees child+effect pool, so no leak proven. Other AI commands may reuse first child and allocate nothing new; do not count 52 every tick. **Unknown:** actual opcode dispatch, allocator return contract on PSP, frequency and time cost on real Go. Diagnostic target: cold child allocation duration and count **vs** warm reuse, without 52 per-node disk writes, and correlate with GE backlog/model packet/accepted display timestamps.
