# QA06 — Fusion Accident candidate generation can fail to terminate when the eligible universe stays below six (2026-11-20)

**Evidence T1: direct pinned PS2 original-source control flow. Actual native PSP compiled code, linked function, edited save, real freeze, PPSSPP and PSP Go remain T0.** This is a *conditional* source risk, NOT a reproduced user crash nor proof that Vanilla normally reaches the condition. No gameplay code, EBOOT, user saves, screenshots or assets modified. Original source pinned `Raikaru/Persona4-Decompilation@363eab8a966d60a9773b45f330f2344329ec4f0a`; P4P runtime frozen `29b0fcfdec70222a4052099b67fb4a11e8d8aff4`.

## Exact new finding (distinct from normal fusion legality / manual inheritance's synthetic host tests)

1. [`src/Yajima/y_list.c::yListSlotFillNearLevel` FUN_002E5AE0 L1358–1393](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_list.c#L1358-L1393) clears and initially scans candidate Persona ID range **0..191**. It requires metadata arcana kind **2..21**, `cmmCommunityIsListable`, `cmmCommunityPassesFlagGate`, `!yListIsExcludedId`, `!cmmCommunityHasFlagGate`, unique IDs and level bounds. [L1478–1500](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_list.c#L1478-L1500): if level >=60 and the initial candidates <3 it clears them; if any candidates remain after that, it returns. This means the widening loop is not entered on *every* low-candidate result, only on the listed conditions.
2. If no initial result remains, the expanded branch at [L1502–1625](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_list.c#L1502-L1625) repeats `yListSlotClear(list)`, widens eligible level range, scans the same 192 IDs with the same gates, increments `outer`, and exits **only** on `while (nearLevelList->count.value <= 5)`. **There is no maximum number of expansions or empty-universe escape.** If eligibility/exclusion flags leave five or fewer eligible IDs even when all levels have been admitted, the exit condition is permanently false. This is a source-level nontermination condition. An actual game state satisfying it is not established.
3. The `fclSubClamped`/`fclAddClamped` implementations [`src/Yajima/y_misc_inferred.c` L230–260](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Yajima/y_misc_inferred.c#L230-L260) explicitly **saturate** in mode1 at bounds; the call in NearLevel uses minimum1 and maximum99. Once the expansion reaches full [1,99], repeating cannot discover different eligible IDs purely by further widening. If availability/exclusion changes asynchronously during the loop, the result could differ; the source loop itself makes no such external state update.
4. This function is called in the **already approved** rare-result paths: normal `0x34 -> 0x36`, triangle `0x4D -> 0x4F`. [Normal source L2238–2305](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L2238-L2305), [triangle L3579–3656](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Event/Fcl/y_fclCombine.c#L3579-L3656). Both `0x37` and `0x50` test an **empty** `yListSlotFillByLevel` result and then fall back to `0x36`/`0x4F`, potentially reaching the same unbounded near-level expansion. Thus testing only the normal non-accident selection path misses this failure class.
5. After `yListSlotFillNearLevel`, normal case0x36 performs `RpRandom() % entryCount2`; triangle case0x4F performs `RpRandom() % listWork`. **If the near-level call returns with count zero** (e.g. its list slot is absent and it returns early at L1384–1386, or from a future patched return), these consumers have a zero-divisor condition. In the ordinary present source, with an initialized slot and a fixed low-eligibility universe, the immediate problem is instead the **nonterminating loop**, not a demonstrated division by zero. A naive patch adding a loop cap **without fixing callers** would exchange a freeze risk for a zero-modulo risk.

## Why this materially changes RESONANCE01 integration planning

- The manual inheritance modal must **not** take over the rare/accident path and assume a selected result exists. The candidate list and final Persona identity are assigned by the accident path itself, which currently auto-transfers prior skill bits onto the substitute. Keep Vanilla rare logic and RNG order unchanged when feature is OFF, and allow manual selection only for validated, resolved **non-accident** result in the first regular candidate. The integration design must not synthesize a substitute or silently force accident selection to the ordinary mask.
- In `fusion-exp`, record bounded `FUSION_RARE_ENTER`, `FUSION_NEARLEVEL_ELIGIBLE_COUNT`, `FUSION_RARE_RESOLVED`, `FUSION_RARE_EMPTY` and final result ID at mode-specific boundaries. Do **not** emit per-iteration logs in a hot potentially endless loop; do not write save or block GE on logs. If a well-justified guard is introduced later, it must guarantee a valid fallback Persona and handle zero candidates **before** `RpRandom()%count`, preserve RNG calls on the ordinary case and not mutate saved Persona; test all three modes separately.
- Host-only reproducible negative model: eligibility=0 and =5 after full saturation -> loop would not exit; eligibility=6 -> exits at first expanded pass with six; initial count=1, level<60 -> returns before expanded loop; initial count=2, level>=60 -> clears and expands. This is a **control-flow proof of the stated condition**, not a PPSSPP replay or a claim that edited-save data creates it. A real integration test needs the actual fused near-level candidate count and mode, plus the clean/modded save controls.
- **Priority:** STAB-FUSION conditional P1 experimental diagnostic, not a reason to replace SEC-01 GPU capacity/bank safety P0, and not justification for blind game-source modifications. The already prepared 18/18 synthetic fusion session tests do not include near-level generator exhaustion or the original accident FSM.

**Falsifiers / unknowns:** Original gameplay progression may ensure >5 eligible Persona for any reachable rare state, in which case this exact failure is unreachable in clean play. PSP recompiler may differ from pinned PS2 source. The actual user's reported edited-save Compendium or reinforcement freezes have not been attributed to this fusion code. Recheck candidate gates and linked generated object before modifying native runtime.
