## 1. UI-D — Weather News black title source now HIGH-confidence matched to screenshot position (I + T1 anchor; sprite ID still T0)

- **Visible in private P4P #106:** the small, dark `Weather News` lettering sits **behind/below the six forecast cells**, starting near native **x≈124, y≈148**; Golden places a bright title toward top-left instead. This is a concrete source/position similarity, not a claim that Golden's texture/skin is Vanilla.

Ordinary 2D conversion `target_sx=480/640=.75`, `target_sy=272/448=.60714286` maps its **source anchor to screen (123.75, 148.14)**, nearly exactly matching the **observed dark text**. The source `rgb=0` and alpha `0xCC` are consistent with the dark label, not with a missing yellow label.
- **New stronger hypothesis (T1 code + I spatial match; semantic identity T0 until one sprite-record dump):** the mispositioned/low-contrast label **is likely this record 1**, not all six weather cards or `p4_forecast_weather`. To prove, log/dump `handle->sprites[0]` record1 separately and/or suppress exactly that one draw for a single PPSSPP test frame. Record actual source/post-projection bbox, texture resource ID and opacity; confirm all days and animation states.
- **Do NOT globally move or brighten all calendar sprites.** The six cells are separately drawn by `calDrawDateCell` and `calDrawWeather` in both phases at source `x=6*(...) + offsets`, y~113 and 163 [L2650–2675]. There are two user goals to distinguish: (a) matching Golden top-left title is a **Vanilla style choice**, not proven original PS2 correction; (b) making current black title readable without overlapping would be a scoped UX patch. If approved, prototype only the one record's position and colour after record proof; do not replace the whole TV layout and re-run title/movie/field-HUD regressions.

## 3. UI-F Config menu #48 — important correction: different content/flow, not evidence for simple x-shift

- Actual paired screenshots: **Golden shows 5 settings plus top `Confirm`**, while P4P displays **six settings plus bottom `CONFIRM`** (seven rows total). Shared option names are at different row orders/y-positions, and fonts/UI skins differ. **The earlier single description 'P4P config right-shifted' is unreliable and is superseded**; it compares **different UI compositions**, not identical controls. The apparent P4P first menu black bar is farther **left** than Golden's `Confirm` bar when each 480px view is aligned, but those bars are **different semantic rows** and should not be used to derive a delta.
- Original [`src/Camp/cmpConfig.c` `cmpConfigDraw` **FUN_0035D0A0**](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Camp/cmpConfig.c#L447-L671) uses one `origin` plus per-row `motion[].position`, and positions seven Vanilla menu option rows; [`cmpConfigDrawOnOff` **FUN_0035DFB0**](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Camp/cmpConfig.c#L718) renders separate option toggles/arrows. Source owner is verified T1 but **no shared +X/-X correction target is established** by #48; keep UI-F **evidence gathering/hold**, not build-ready alongside UI-A.

## 5. Negative controls: golden UI is not a 1:1 version of Vanilla menus

- #1 title is obviously different design; title flashes are a **temporal framebuffer** bug to test, not evidence for replacing Vanilla logo/picture.
- #5 Golden shows three visible save slots / P4P a different populated slot and help layout; compare same game-state slot count before treating as missing data.
- #10 Velvet menu items differ (including additional functions/availability), #16 status palette and level, #22 unlocked menus, #27–38 skills/items/stats/equipment, #41 character levels, #47 quest story state, #57 gear, #70 shop branding, and #93–105 dates/weather are often **different content, assets or progression**. Gold/PSP geometry can guide composition, but these are **not** proof of a performance, graphical or gameplay regression.
- #38 character status portrait and left menu/card frame are a useful **negative control**: they are already roughly similarly anchored, so changing the renderer's **global** image X/Y ratio for Social Links would risk breaking a mostly aligned screen. Likewise the **Town Map #97** and **CRI logo** are previously known-good constraints.
- UI taxonomy for implementation: **shape (radial fan) != picture sprite (shop logo) != textured/masked portrait != font rows != whole-screen background != title/movie/RTT feedback != game-data option list**. Every change needs an explicit source owner, same-state frame and an independent test/rollback flag.
