### Exactly what perf06 changed relative to reference perf04/perf05

The actual source-tree GitHub comparison `1b4a369d0dd143a58d90caabc55c9eae523adbd` (perf04) → pinned perf06 yields only **four port C files**: `port/main.c`, `port/memcard.c`, `port/paths.c`, `port/rwsky.c`; other changes are build/test tools. Release [`docs/v027_perf06.md`](../v027_perf06.md) independently reports **820 of 821 game objects identical to delivered perf05 objects**, one modified game translation unit for Margaret fusion return. **Do not infer that the 821 objects are identical to perf04**; game-object equality is specifically versus perf05 artifact set.

- **Texture MIPs (perf04 restored):** `rwsky.c` reverted perf05's overly strict PSP raster format-bit condition and retained mip chain size/format/memory rules from perf04. Current [`mip_levels/mip_decimate` L1090–1132](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1090-L1132) builds power-of-two indexed/truecolor mips via point-decimation; [L2713–2746](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L2713-L2746) enables `GU_LINEAR_MIPMAP_NEAREST` when eligible. It is **both** a performance/bandwidth control and a potential thin-detail visual-quality issue. **Never globally turn mips off to sharpen the school floor** without Go FPS checks.
- **Weather alpha scope:** `port/rwsky.c` and two callsite modifications from `tools/psp_census.py` make a **localized** weather-calendar alpha-writing change, not a wholesale framebuffer-alpha conversion. Regular weather-mask correction was reported working on Go; full Golden weather UI layout remains open. Do not globally revert or conflate weather mask with text position.
- **Rush/Stop:** `tools/psp_link.py` corrects data alias to original vertical anchor **0x7615A0**. UI still requires class-specific widescreen review, but don't remove the alias because Golden differs semantically.
- **PSP Go storage and saves:** `port/paths.c` supports internal `ef0:/`; `port/memcard.c` synchronizes the selected device; `port/main.c` adds coupled runtime digest verification and boot/source safeguards. Keep user storage and save protection in perf07.
- **Fusion Margaret pose:** `tools/psp_census.py` applies a **single original game-object patch** to `src/unplaced/unplaced_inferred_0033d310.c` after `MT_Scene_GetResListHead(3)` is ready. It dispatches animation **13** to resource type **0x38**, once at the original field **8/3 room 1** return before fade; PPSSPP replay control/candidate showed sitting vs standing. Don't 'fix' animator or resource lifecycle globally based on this one scoped case.
- Renderer pipeline, 3D GE submission, skinning and mesh cache, video/audio code mostly **unchanged from perf04** in this perf04→perf06 diff. That allows **perf04 as a historical hardware/performance control** where input/scene matches; do not claim perf06 originated as perf05 HEAD with full inherited geometry changes.

## Runtime-image provenance and diagnostic mode trap

- At pinned runtime, [`port/main.c` L18–35](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/main.c#L18-L35) selects `p4.log` for regular EBOOT, `p4-timing.log` for `P4_FRAME_TIMING`, or `p4_hwdbg.log` for `P4_HW_PROFILE`; the last loads **`p4data.hwdbg.bin`**, not normal `p4data.bin`. Wrong mixing can cause false crashes/boot.
- [`tools/psp_hw_debug.py` L25–70](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_hw_debug.py#L25-L70): `--release` enables `P4_VERIFY_RUNTIME` with two link passes, digest embedding; `--frame-timing` **requires** `--release` and enables a separate light `P4_FRAME_TIMING` variant; `--ge-dump` creates a serial render variant with different pipeline configuration; non-release normal hardware profiler uses `P4_HW_PROFILE`. The standard `tools/psp_link.py` default clean path defines neither profiler macro. **Never compare a serial GE dump frame timing to the regular pipelined perf06 FPS as if both were the same**.
- [`tools/psp_hw_debug.py` L157–165](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_hw_debug.py#L157-L165) emits `manifest.json` with hashes of port .c/.h, original 821+ game objects, ELF/PRX/PBP/data, mode flags. The real perf06 release docs mention that manifest; **the manifest bytes / PBP / private object tree were not available directly in this session**. For a true binary audit, hash compare EBOOT/p4data/p4str and locally examine `p4.elf` symbol and `build/psp/missing.txt` while preserving user files. A GitHub source commit + a release document alone cannot validate compiled symbol reachability or missing `func_004c8708`.
- `port/main.c` L469 logs startup build ID, and L484–510 logs real boot free/maxfree/stack; `FPS` and `BATCHSTATS` marker files under game directory enable modes at startup (L460–465). The log writer is buffered; last ~100ms may be unavailable after hard crash. **Crash packet should record the three artifact hashes, mode flags, last actual scene ID and GE list bank, not only build label.**
