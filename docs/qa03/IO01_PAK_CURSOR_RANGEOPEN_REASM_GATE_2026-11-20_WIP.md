## 2. NEW high-value static linking/reassembly discriminator: func_004c8708 may be a missing stub (conditional)

- Original [`src/promoted/code1_004c.c` L102–109](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/promoted/code1_004c.c#L102-L109) exposes `func_004c8708` **only as `INCLUDE_ASM`**, **not** an original C body. Complete frozen PSP [`port/files.c` L1–210](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/files.c) has open `func_004c85a0`, read `func_004c9010`, close `func_004c8a60`, status `func_004c9820`, **but not `func_004c8708`**. Frozen linker [`tools/psp_link.py` L24–26](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_link.py#L24-L26) enumerates 15 port C modules; GitHub code search of the project default branch found no definition of the range opener, but **default-branch search is not frozen-build proof**.
- Crucial new direct observation: frozen [`tools/psp_reasm.py` L25](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_reasm.py#L20-L27) sets **`CRI = 0x004C0000`**, and [`reassemble()` L471–480](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_reasm.py#L471-L480) **refuses all retail functions `addr >= CRI`** (after `not known start` and `sdk` checks). The target **`0x004C8708 >= 0x004C0000`**. It therefore cannot be supplied by this automatic retail-reassembly route. **This arithmetic check was executed in a host-only synthetic inspection**; it is not proof how a shipped EBOOT resolved the symbol.
- Frozen [`tools/psp_link.py` L140–201](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_link.py#L140-L201) first subtracts symbols already defined by game objects, port modules and SDK libraries; tries retail reassembly for the remaining; writes **`build/psp/reasm_refused.txt`**, **`build/psp/missing.txt`**, and compiles **`build/psp/stubs.c`** for unresolved symbols. [`port/main.c` `p4_missing` L325–342](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/main.c#L325-L342) logs `missing <name> from <caller>`, a backtrace, and returns **0**.
- **Source-derived conditional result:** If `sdkPak2.o` links the `func_004c8708` reference, and **no other input already defines it**, then reassembly refuses at the CRI cutoff and the linker is expected to generate a **`func_004c8708` logging stub returning 0**. `sdkPakStartEntryLoad` will put that null handle into its entry slot and immediately pass it to `func_004c9010`; that reads `h->offset` ([files.c L153](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/files.c#L147-L157)), a **potential null-dereference** on actual package-entry loads. **Do NOT state that the real EBOOT contains the stub or that a package-entry request has ever been invoked.** Only generated `missing.txt`, `reasm_refused.txt`, `psp-nm` of actual EBOOT/ELF or a real `p4.log` can settle it.
- Other source facts: `port/files.c` uses `Handle.used` / `NUM_HANDLES=16` and checks index hash/file container at open. A future range opener must maintain original relative `start_sector` and `sector_count` **within** `Row.size` while handling split 1-GiB parts and handle-slot exhaustion. *Exact retail semantics of `func_004c8708` are ASM-only, not decoded here*, so do **not** implement a guessed range open in perf07 without analyzing the original body and approved A/B.

## 3. Actual host-only source-model checks (not an EBOOT test)

Constructed in a one-shot JS tool sandbox without game bytes: three distinct 2,048-byte sectors filled with `H`, `D`, `E`. A direct model of frozen `func_004c9010` increments **local** offset only; two separate `read(h,1)` calls produced **`H,H`** and left `h.offset=0`. Original ADXF model commits completed `skpos` each call; produced **`H,D`** and finished at `h.offset=4096`. Explicit assertions passed. Same script checked **`0x4C8708 >=0x4C0000`** and passed. These are **simple modeled control flows**, not compiled native C or a PPSSPP/PSP Go hardware test. No archive bytes were accessed.
