## Upstream performance evidence, not our benchmark

- Historical b390–b400 PSP session, 333 MHz and profiler off: Entrance ~15→~23 FPS, Junes West Entrance ~15→~23 FPS. **Not** a fresh b450 versus b388 A/B; Heaven 30 FPS claim was explicitly withdrawn because the scene was actually Junes.
- `static_flat`: upstream source claims PSP Entrance ~67.2→50.5 ms, CPU -15ms for the tested diagnostic builds; `skin_wsplit` mode 2 claims ~50.5→42.5 ms in a separate recorded configuration. These **cannot be added** to predict our current FPS.
- `p4_ge_compile`: Heaven compiled-list data 2.65→1.62 MB, unchanged picture and unchanged CPU in that CPU-bound test.
- `p4_2d_cache`: b450 source comment cites one Margaret-dialogue CPU reduction around 0.7–0.8ms, but `docs/perf_status.md` says Heaven differences are within noise.
- b450 validation: targeted host tests and frozen build passed; some wider fixtures fail; final b450 XMB executable **not** given a gameplay validation on PSP. Movie hangs, heap fragmentation and fusion-glow flicker remain open.
- Our public `docs/perf_status.md` contains earlier device data, but **no accepted-present b259 or post-UI-WHEEL/REND-CARD test on PSP Go**. Our `port/frame_timing.h` provides optional 32-frame p50/p95 timing for a dedicated hardware build; must validate frame semantics and overhead before comparing.
- Therefore relative FPS between b450 and RESONANCE01 is **UNVERIFIED**. G2 remains `P0_UNVERIFIED`; no speculative device promotion.

## Recommended work packages (no code changed by this study)

1. **Source/local delta check + host-only baseline.** Verify b259/current experiment source (not just public perf06) for matching equivalents. Maintain archived b259 and UI-WHEEL-02/REND-CARD-01. Set consistent scene IDs, settings and graphics checks. Do not claim new FPS.
2. **PERF-SKIN-01 / one opt-in skin-format experiment.** Use existing `skin_batch` as anchor; compare a constrained set of GE-weight group, flat/colour cases against upstream `skin.h`. Choose **one** small independent variant, enforce weights/vertex/winding/alpha byte-level tests, GE budgets and rollback. Isolated PPSSPP candidate only. Skin memory/GE ownership must be checked before device testing.
3. **PERF-2D-01 / 2D cache extension.** Compare our existing `p4_ui_state_cache` eligibility to b450's epoch/cache, with retained fallback for unusual blend/depth/RTT/CLUT/screen-copy cases. Use battle/Camp/Margaret controls and overlay pixel A/B; no bulk integration. Performance metrics only if reliable.
4. **PERF-STATIC-01 / architecture feasibility.** Only if profiling reveals significant re-recording of static scenery, sketch a budgeted persistent-list owner and generation/GE retirement contract. Do not import `static_list.h` plus `p4_ge_compile`/b439 in one pass. Quantify CPU, list words, allocation pressure, cache hit/miss and fallback.
5. Consider `P4_HOT` only after native map + miss profiling; defer default-off `p4_ui_native`, split/cloud/guard disabling, broad renderer switching and untested offline pack consumers.

**Decision:** the strongest *tested upstream* CPU gains came from static-list flattening and grouped flat skinning; the strongest *near-term transplant anchor* in our public code is `skin_batch` rather than a nonexistent persistent static-list subsystem. First experiment should remain opt-in and PPSSPP-only. **Do not claim our current performance is slower or faster than b450 until measured on comparable hardware/route.**
