## Ranked opportunities, with frozen perf06 controls and falsifiers

### XP-01 / SEC-01 — real GE list capacity + lifecycle tests, **highest direct source relevance**

OoT [`gfx_scegu_reserve_list_memory` L160–174](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/src/port/psp/gfx/gfx_scegu.c#L160-L174) calls `sceGuCheckList()` against `sizeof(list)` and includes **4096 bytes** of pending command reserve plus payload+8; when full, `sceGuFinish`, `sceGuSync`, `gfx_scegu_start_list`. Later [L375–380](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/src/port/psp/gfx/gfx_scegu.c#L375-L380) **rebinds the current draw target** after a list restart, because the SDK restores a saved framebuffer. Note carefully: **OoT 4096 is bytes, while upstream P4P/b388 `LIST_RESERVE=4096` is words**, so never copy the same literal as equivalent capacity. Its [host test L213–232](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/tools/tests/test_psp_ge_submit.py#L213-L232) explicitly forces list near end and checks in-flight vertex allocations remain protected across rollover.

P4P frozen [`rwsky.c` L458–464](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L458-L464) has only **65,536 words/list**, cached list+pipeline=1, multiple raw GE writers and no complete bounds guard; see [SEC-01 writer census](SEC01_GE_LIST_WRITER_CENSUS_2026-11-20_WIP.md). **Transfer the test pattern first, not OoT's synchronous rollover implementation**: P4P has alternating lists, GE stall-gating, frame bank, cached CALL/replay and RTT; midframe finish/sync/start could destroy overlap, cached state or scene correctness. Isolated host harness tests direct writer boundaries, reserve tail, long replay memcpy and mock list 0/1, plus new list target/RTT rebind checks. First instrumented perf06 scene **Junes F009_004**, positive stress fog/reinforcement, negative **School F006_002**. T1 hazard; overflow still T0.

### XP-02 / REND-01 + REND-05 — GPU shadow and depth ownership, **strong visual hypothesis**

OoT [shadow source](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/src/port/psp/gfx/gfx_psp_shadow.inc.c) renders an offscreen **64x64 RGBA** mask with a dedicated scratch color target, **disables GU_DEPTH_TEST and depth writes** (`sceGuDepthMask(GU_TRUE)`), uses alpha/stencil, GE copy to a cache allocation (`sceGuCopyImage` + `sceGuTexSync`/`sceGuTexFlush`), and restores render state. [Validation docs](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/docs/psp-gpu-shadows.md) report **4,129 host mask comparisons** to original CPU masks; they explicitly do not prove actual GE precision/perf scheduling.

P4P [`rwsky.c` L1194–1216](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1194-L1216) explicitly shares main depth with RTT, and [L1285–1300](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1285-L1300) rebinds only color/viewport/scissor, not a new depth. **New candidate discriminator, not automatic patch:** if a specifically identified Junes 128x128 shadow RTT needs a **color/alpha mask only**, could its depth writes/clears be suppressed or isolated, preserving main scene depth? First trace PS2 source camera clear mask/order and P4P real camera+0x60/projection/draws: if shadow needs self-occlusion, disabling depth would be wrong. Alternative full separate depth buffer must meet eDRAM budget; don't blindly allocate. Screen-space top-left rectangle artifacts vs world-locked shadows remain a falsifier. Preserve 3D visuals and perf06 MIP/weather baseline.

### XP-03 / TEX-02 — texture/address validity and offline content preparation, **medium**

OoT [`psp_texture_manager.c`](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/src/port/psp/gfx/psp_texture_manager.c) rejects invalid texture ID zero and overflowed byte dimensions, aligns GE rows to **16 bytes** (T4 width 32, T8 16, 16-bit 8, 32-bit 4), prevents failed growth from moving the arena pointer or overwriting a previous texture, and invalidates old GU binding when an allocation changes address/format. It waits for outstanding GE draws before reusing VRAM cache regions in [`gfx_scegu.c` L176–185](https://github.com/z2442/oot-PSP/blob/395ce42be9a03d564f0b6a30f3726b920a8f1d4d/src/port/psp/gfx/gfx_scegu.c#L176-L185). Compare to P4P `rwsky.c` raster create/generation, RTT slot reclaim and CLUT cache for Teddie/portrait wrong texture, **not** assert identical bug.

re3-psp's offline TXD/DFF/IFP IMG/DIR conversion and REGTA native TXD cache suggest a measured `p4data.bin` prepack trial for **only demonstrably hot Junes/School textures, safe mips or skinned data**, while preserving actual original PS2 assets and avoiding any uploaded copyrighted content. P4P already has `p4data.bin`, native swizzle/mip logic, GE caching, and `p4_mipmaps=1`: do not create another permanent cache prematurely or replace pixel appearance by guess. Compare asset hash, byte size, PSP RAM, load/IO, mip chain and real Go p50/p95 at identical F009_004 + F006_002 saves. Deliberately low priority until SEC-01 and file-loader IO-01 reachability are checked.

### XP-04 / QA-01 — bot safety architecture, **high payoff when automated test development resumes**

LCS [`stress_test.py`](https://github.com/elmasas/lcs-recomp/blob/main/lcs/scripts/stress_test.py) provides a concrete role split: disposable save/config copy, source-directory content hashes (and symlink handling), watchdog/timeout, log+summary, exit status and RAM peak, plus an opt-in external state/command protocol. In P4P, build equivalent **host-only PPSSPP WebSocket controller** around the already documented [PPSSPP WebSocket API](PPSSPP_BOT_INTERFACE_WIP.md) and [BOT v2](PLAYTHROUGH_BOT_REAL_INTERFACE_V2_WIP.md), not embedded per-frame filesystem polling. Record route ID/version, baseline EBOOT/data hashes, save hash, scene Fxxx_xxx, frames/presents, checkpoint origin clock, last 30 seconds input/GE/IO/log; use prompt human diagnosis on failure. Respect **71.58 min 32-bit absolute route-clock wrap** documented elsewhere; never use raw PSP clock as an indefinitely monotonic checkpoint key. Begin save-loading + intro smoke, then Junes and a scripted battle, only later multi-hour playthrough. **This is a design candidate, not a running bot.**

### XP-05 / MEM-CARD — duplication avoided

OoT fork says it writes temporary save then swaps and retains `.bak`; however **P4P already does this**: [frozen `port/memcard.c` L146–188](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/memcard.c#L146-L188) temp write/flush/sync/backup rename, and [L102–109](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/memcard.c#L102-L109) fallback reader. **Do not propose implementing it again.** Potential tests: power-loss/interrupted/low-free-space private save clones and both card slots, but not a code-change recommendation without failure evidence.
