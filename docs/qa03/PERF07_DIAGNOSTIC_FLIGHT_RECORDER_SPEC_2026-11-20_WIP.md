## Core feature set by cost and diagnostic value

### D0 — always available low-cost causal milestones (required)

A preallocated small `P4_DiagRecord` ring, **proposal 512×64 bytes = 32 KiB** plus up to **16 KiB** counters/events, fixed ring/no malloc in hot path, bounded contention and overflow counters. Do **not** allocate existing `p4_memstat`'s ~768 KiB census table just for LITE.

Per completed/drawn/displayed frame, record time, monotone in-session `frame_seq` and `tick_seq` separately, `scene_key` (only if actually resolved/validated; else UNKNOWN), `task_or_phase_key`, `render_bank`, `drawn/skipped/presented` booleans, number of draw calls, RTT targets, command list used **words for bank 0 and 1 separately**, list words at **post-overlay FINISH/END**, indexed/submission status and GE/wait/display sequence counters. Actual final hi-water needs a **writer-level maximum** and reservation **before** writes, not just subtracting pointers after an OOB write; bound all raw/SDK writers and retain FINISH+END tail. A failed start/finish is an event (include actual return code), not a normal frame. Lifetime invariant: **no bank reused if earlier GPU submission referencing it unfinished**. A watcher may log a suspected violation, but logging alone is **not a memory-safety fix**.

Timestamp stages: task/game-tick entry/exit; start CPU frame build; GE list-start accepted (record return, QID); GE submission FINISH; GE callback finished with seq, bank; flip thread submitted display/present timestamp; movie begin/end resets; intentional skip. Render `CPU build`, `GE queued→finish elapsed` (queue + wait + GPU busy; **not** pure GPU execution), `finish→present` (display/vblank delay), `present→present` actual user-visible FPS, and time inside `sceGuSync/flip_wait`. **Overlaps exist:** never add CPU+GE durations to assert exact total frame time. Correlate sustained queue growth and heavy command/vertex traffic with screen-present stutter.

Clock: `sceKernelGetSystemTimeLow` is microseconds in a wrapping `u32`, valid **modulo subtraction for short spans**; for 72min+ bot/hang archives prefer pinned SDK `sceKernelGetSystemTimeWide` after build link verification, or extend an epoch. Do not use absolute 32-bit time for session timestamp ordering, frame comparisons must handle wrap. All durations from monotonic clock, not RTC.

LITE window: 32-frame (existing) plus **128-presented-frame** rolling distributions; p50/p95/p99 optional from bounded fixed bucket/histogram (no unbounded qsort per frame), FPS presented and game tick rate separately; log CPU-build/GE completion backlog/flip wait, draw/skip counts, per-scene summaries, **max GE-list words per bank** and threshold/risk flags. No full pixel dumps or frequent VRAM reads.

### D1 — automatic incident recorder (required)

Trigger when (proposed initial thresholds, NOT measured tuned values): **3 of last 5 drawn wall intervals >50,000µs** (20-FPS goal), any interval **>100,000µs** (severe), `ge_queued - ge_finished` unexpected backlog, **250ms watchdog** / 1s gave-up, any list above **~90% of usable capacity** after keeping conservative tail reserve, rejected GU start/finish, RTT allocation/fallback, anomalous I/O **>20ms** (not proof IO *caused* the slow frame), negative memory/asset integrity event. Distinguish intentional dialogue/scene loads/movie/fps cap and deliberate skips. Thresholds are initial design candidates, tune after hardware samples.

For each trigger: preserve **pre-trigger 128 records and up to next 128 records**, only fixed amount, with trigger reason, first culprit candidate, source tag and list-bank state. Never dump synchronously in GE callback or while a memory semaphore is held; use **existing p4_log writer every 100ms**, flush condensed compact structured event/small ring segments at safe point with bounded queue. Overwrite/overflow and dropped-event counters printed. Optional user-requested final snapshot while gameplay paused safely; crash/power loss can still lose last unflushed interval. New `p4diag-lite.log` or fixed binary `p4diag.bin` output **separate** from `p4.log`; on `ef0:/` and `ms0:/` use `p4_game_dir` (existing `paths.c`) and non-destructive unique build/session names. **Do not overwrite saves or share private P4 game assets.**

### D3 — diagnostic classification: report observed co-occurrence, not invented root cause

- **Presented interval slow + GE completion backlog high + CPU build normal** ⇒ **GE queue/consumer bottleneck candidate**; still check watchdog, display flip and list integrity. It may also be GPU-bound, but queue delay is NOT direct GPU busy time.
- **Presented slow + long CPU game task + GE queue normal** ⇒ CPU logic/animation candidate; cross-check I/O wait and thread scheduling.
- **CPU slow + `p4io` semaphore wait / `sceIoRead` long in same interval** ⇒ I/O-blocking candidate, but unrelated concurrent load still possible; need repeated co-occurrences and task caller.
- **GE finished + display not shown** ⇒ flip/vblank/display scheduling candidate; **not** a live-GE-bank memory overwrite by itself.
- **Game tick advances but no rendered/presented frame** ⇒ intentional frameskip candidate vs hang; task and skip debt decide. **Never compute present FPS from tick count**.
- **Wrong RTT target / clear flags / missing shadow** ⇒ fidelity bug candidate independent of CPU/GE speed; camera order logging required.

Each incident report must show **facts, confidence (I/U/T1/T2/T3), alternative explanations and next discriminating test**, not a label `GPU root cause proven` generated from timing heuristics.

## Proposed compact event schema / offline host parser (versioned)

One record is fixed **64 bytes**, little-endian; actual field layout only after host ABI/packing verification. Required fields: `schema_version`, `build/profile`, `frame_seq`, `tick_seq`, `timestamp_lo`/epoch, `event_id`, `scene_key or UNKNOWN`, `task_key`, `bank`, `begin/end list words or max`, `ge_queued/ge_finished/shown`, `present_us`, `cpu_build_us`, `wait_us`, `flags`. When a 64-byte record cannot hold all telemetry, **do not silently truncate**: encode tagged supplemental events with referential frame sequence or increase fixed record after measuring RAM; host tests must validate binary layout, wrap and missing/corrupt file. Bundle `manifest.json` with **source commit and exact EBOOT SHA256**, `p4data.bin/p4str.bin` hashes, PSP model/clock, test scene, selected diag flags, `p4.log` tail and counters. Host parser outputs CSV + JSON summary and incident timeline **without gameplay asset payloads** and can optionally correlate PPSSPP bot state for T2.

## 2026-11-20 QA06 correction — recorder zero-POST blind spot and hard-power durability ceiling

**Read [source proof + 10/10 executed new synthetic C host regressions](DIAG_D1_PARTIAL_STALL_HOME_CRASH_DURABILITY_2026-11-20_QA06_WIP.md) FIRST for D1 integration.** The historic 23/23 C model (still correct for its covered cases) has an important untested failure: [`ring_trigger`/ `ring_push` L44–61](host_tests/p4diag_host_v1.c) only transition `CAPTURING→SEALED` upon **128 subsequent events**; [`ring_validate` L69–74](host_tests/p4diag_host_v1.c) forbids early seal and [`export_begin`](host_tests/p4diag_host_v1.c) invokes it. The user-observed freeze could stop new gameplay events immediately, so no export is ever initiated. **Correct design:** independent scheduled worker observes game/GE/display heartbeats and can seal 0..127 POST, carrying `PARTIAL/NO_PROGRESS` plus original trigger/sequence, without assuming the absent tick is itself the root cause. For zero PRE/POST, ensure a typed event (not invalid zero-event file). Preserve 128 POST normal case/CRC/wrap. New [host-only 10/10 C fixture](host_tests/p4diag_partial_seal_qa06.c) validated with GCC14.2 O2 and Clang17 ASan/UBSan in this QA06 rotation, **not a PSP runtime module or filesystem test**.

**Honest crash durability limits:** a RAM `SEALED` ring survives IO errors only **while the process remains alive**. Frozen [HOME `port/lifecycle.c` L44–62](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/lifecycle.c#L44-L62) waits for **card save lock**, not a future independent recorder worker, then calls `sceKernelExitGame`. On hard power cut/kernel deadlock the writer cannot guarantee anything after the latest successfully synced journal. Copying [`port/memcard.c` temp/backup sync](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/memcard.c#L146-L189) without its lock/cleanup is not acceptable; holding card_lock over multi-tick export may block user saves and HOME. Worker must do bounded nonblocking coordination and actual checked temp-write/close/device-sync/reopen-readback/rename/sync/final CRC before ACK; synthetic host `persisted_and_verified` bool is not PSP storage verification. Report `NO_INCIDENT_AVAILABLE` honestly when exit/power precedes any commit. Existing baseline `p4.log` is best-effort and may lose even queued data on short write. Avoid pre-exit synchronous disk flush in unsafe callback unless bounded and validated.

**New SEC-01p source warning for any freeze trace:** [19:00 T1 proof](SEC01P_FREEZE_PROBE_BANK_IDENTITY_2026-11-20_WIP.md) shows `FREEZE frame...list` points to the **next selected GE command bank** after `pipe_set` toggles in default pipeline; not a valid last-submitted/shown bank label. D0 must separately capture submitted and selected-next bank, GE completion QID and actual accepted display.
