Those are source conditions, not measured crash fixes.\n\n## 1. Highest-impact NEW code difference — Junes shadow-camera projection / RTT (T1 code, visual fault T0 for perf06)

- Actual P4P [`camera_projection` `port/rwsky.c` lines 3770–3777](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3770-L3777) **always builds a perspective matrix**; no `CAMERA_PROJECTION` (= RW camera +0x14) branch. The same matrix is reused by [`set_camera` L3779–3801](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3779-L3801) *and* guard/model-to-clip projection [L3890–3900](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3890-L3900). Thus this is not limited to a single postprocess sprite.
- In actual b388 [`port/guard.h` lines 128–145](https://github.com/dreikk91/persona4-psp/blob/b388/port/guard.h#L128-L145), `camera_projection` checks `CAMERA_PROJECTION==2` (`rwPARALLEL`) and emits **orthographic** matrix. b388 [`docs/visual_issues.md` Junes West investigation](https://github.com/dreikk91/persona4-psp/blob/b388/docs/visual_issues.md) identifies the floor pass as a **hero silhouette shadow**, despite 'renderTex for shadow' / 'reflection' naming confusion. The PS2 first draws hero+fades into **128×128 RTT**, then a non-indexed Im3D quad over the floor reads it; prior b328/b329 perspective projected the hero near a corner, correcting to parallel moved it near centre. Additional b330–b333 fixes were required for nonindexed textured camera Im3D quad, alpha/DATE fade, clamp, and clear into the right camera raster.
- The current P4P [`im3d_draw` lines 11192–11243](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L11192-L11243) recognizes culling for Shuffle-specific draws, **not** b388's `p4_field_shadow` nonindexed camera-textured Im3D branch [`b388 rwsky.c` L2979–3000](https://github.com/dreikk91/persona4-psp/blob/b388/port/rwsky.c#L2979-L3000). Exact text search in current P4P `rwsky.c` found **no `p4_field_shadow` or `p4_shadow_fade` switch**. This makes the upstream shadow pipeline a **well-mapped missing feature/compatibility difference**, not a promise that all current Junes frame-time loss comes from it.
- Current P4P has RTT allocation and camera-texture GE draws [`rtt_get/rtt_bind_target` L1197–1300](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1197-L1300), so a pass may still cost CPU/GE without a correct resulting floor shadow. **Do not infer that perf06's RTT is free, nor disable it broadly to improve FPS.**
- **Proposed isolated sequence:** P0 baseline F009_004 same camera/save, enumerate `rtt passes/atomics/clears`, 128×128 target, projection type at camera+0x14, first target clear, GE viewport/scissor/depth and texture samples. P1 implement **only orthographic camera projection** locally with corresponding guard maths/cache invalidation (do not use blanket b388 renderer); test all parallel cameras + perspective control. P2 separate scoped non-indexed camera-textured Im3D draw and DATE/fade+RTT clear only if P1 reveals missing shadow; compare before/after game image and PSP-Go p50/p95. Do **not** combine with UI, culling cards, fog, or generic performance changes.

## 2. Black dungeon/fog lines — identified original Field-Noise compositor (new T1, symptom route T0)

- Original [`src/unplaced/unplaced_inferred_001853e0.c` **`FldNoiseUpdate` FUN_00185850** L203–585](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L203-L585) constructs **70 textured 64×64 source grid tiles** (7×10), **14 horizontal 640×32 source bands**, **three concentric ring pairs**, a **640×448 source feedback quad**, and queues state/draw/end callbacks with `PrimQueueDrawPrimitive`.
- Specific handlers: [`FldNoiseRenderStateA` FUN_001853E0](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L75-L102) binds first noise texture / blend `0x54`; [`RenderStateB` FUN_001854F0](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L104-L123) second texture/strips; [`FldNoiseOverlayDraw` FUN_00185620](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L143-L164) binds **display-buffer raster** / `0x54`; [`RenderStateSetup` FUN_00185730](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L168-L190) begins mask tag; [`FldNoiseEmitRings` FUN_00185830](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L193-L201) closes it. This is a **multi-layer, feedback-dependent screen compositor**, not only a 3D fog distance parameter. Field tasks can create the noise task [`k_field.c`](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Kosaka/Field/k_field.c).
- On PSP, source 64px vertical grid interval nominally maps to **38.86 screen pixels**, horizontal 32px bands to **19.43px**, when `target_sy=272/448`. Test if alleged black line positions are **screen-locked multiples** of these intervals (suggest seam/UV/feedback) or **move with floor mesh** while the camera moves (suggest depth/cull/guard). Need a **same-scene movie** or consecutive GPU frames; the Golden/P4P stills alone do not prove this routine was active.
- PSP [`port/feedback.h`](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/feedback.h) only converts **strictly uniform axis-aligned six-vertex feedback quads** to up to 30 two-vertex strips; [`rwsky.c` L3558–3578](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3558-L3578) otherwise keeps triangles. This candidate affects screen-copy texture reads but **there is no proof** a specific FieldNoise quad passes this six-vertex eligibility; capture the actual `prim/n` before pointing to `p4_feedback_sprites`.
- The separate 3D explanation remains: [`bind_depth` L2169–2187](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L2169-L2187) explicitly acknowledges 16-bit PSP vs 24-bit PS2 depth fighting for decals and **`p4_decal_bias=0`** [L847](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L847); [`p4_guard_clip=1` by default L906](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L906), but **falls back to 0 if clip/index buffers cannot allocate** [L926–949](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L926-L949), historically linked to floor holes. Before changing bias or clipping, inspect boot log for **`guard band buffers failed, clipping off`**, actual draw depth-write/test, mesh type, scissor and camera. **Never globally disable fog/depth or guard**.
- **Discriminator:** lines move with the camera/ground geometry = world/depth first; steady horizontal screen grid/19px repetition = field compositor/UV; alternation every framebuffer = alpha/feedback; only certain dungeon fields = confirm task creation. Test on Castle and Yomotsu with correct scene IDs, preserve #74 Vanilla white corridor unless user separately chooses black.

## 3. Glow balls, Zio, Apsaras, other fusion light and flicker — actual alpha reader/writer and evidence separation

- P4P [`rwsky.c` L893–901](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L893-L901) defaults **`p4_dst_alpha_passes=0` and `p4_alpha_pixel=0`**. [`draw_body` L3495–3550](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3495-L3550) distinguishes masked alpha writers (`pixel_mask==0x00ffffff`) and **destination-alpha readers with blend `0x52/0x54/0x58` using the screen raster**; many sub-half-PS2-screen passes are intentionally skipped. This can remove intended soft VFX or avoid hard square artifacts, depending on the **actual scene primitive and surface**. It is not a verified Zio cause.
- Upstream [`docs/visual_issues.md` b366–b383 Fusion glow](https://github.com/dreikk91/persona4-psp/blob/b388/docs/visual_issues.md) **measured on PSP** a separate **post-fusion new-Persona glow flicker (Satan)**: two consecutive frames alternate darker/brighter doubled glow layers; colour clears each frame, depth-only camera clear also occurs, 80 tiles use subtract blend `0x42`, then `0x58` screen copy covers **about seven screen areas/frame**, multiplied by destination alpha. Evidence excludes tested `p4_ge_raw`, `p4_skin_list`, frameskip, visual-bit skipping, previous-frame keep as its original root. **Do not automatically claim the user's Apsaras/Zio effects are identical to this Satan effect**, but the writer→reader→framebuffer-bank route is now a concrete high-priority trace.
- A frame-pair test needs both buffer banks / clear flags / alpha writers, texture alpha and compare the **same animation frame** in PPSSPP, not alternating arbitrary time samples. Existing `fusion_visual` sampling/logs and `p4_probe_2d` can narrow draws; `p4_probe_2d` is capped to 64/48 draws and is not a complete trace. For each VFX type record `draw prim + raster + blend + mask + bbox + DATE + skipped count + GE time`. Any global `p4_alpha_pixel=1` may reintroduce dark minimap bands, and enabling skipped readers may bring back hard square puffs; never ship an unscoped toggle.
- Original [`effPolygonThunder.c` `ThunderBoltUpdateStrip` FUN_004956B0](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Graphics/Effect/effPolygonThunder.c#L183) and [`effPolygonWind.c` `FunnelWindUpdateStrip` FUN_004A2310](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Graphics/Effect/effPolygonWind.c#L251) are actual effect geometry families. **The Zio spell's precise mapped family, particle ID and Apsaras fusion effect owner remain T0 until resource/dispatch proof.**

## 4. Dojima #105 blue triangular screen-edge leak (new I candidate; source T0)

- Directly revisited private matched Golden/P4P **#105** at normalized 480×272. **perf06 has distinct flat cyan/blue regions at both bottom corners**, strong at right starting near pixel x437/y215 and left across lower y254–271; Golden screenshot doesn't show comparable pure-blue corner. This is a visual finding only; camera/view, model geometry and day state differ. The blue portions resemble **clear-colour/exposed-background holes or near-camera geometry bounds**, but their true source is not proven; original Vanilla PS2 matching camera needed.
- Source guardrails: `p4_cull_far=0`, `p4_cull_cover=0` [`rwsky.c` L10846/10860](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L10846-L10860) default, making **aggressive far-cull an unlikely baseline cause**. Guard clip can fail open on allocation as above; inspect `guard band buffers failed`, sky/camera clear colour, final world-sector draw/scissor and whether source camera traverses beyond authored field mesh after 16:9 extension. Do **not** just repaint the holes blue/black or shrink the viewport. Add short side-by-side fixed camera capture for #105 to geometry QA.

## 5. Separate upstream fidelity candidates — check perf06 before adopting

The same b388 source [`docs/visual_issues.md`](https://github.com/dreikk91/persona4-psp/blob/b388/docs/visual_issues.md) documents other effects beyond existing user bug register. They are **not automatically proven user-visible perf06 bugs**:

- **Rain PTank / rainy days:** upstream b270 needed matrix-cluster support; **P4P perf06 already has matrix-based particles** in [`draw_ptank_body` L10685–10830](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L10685-L10830) (`PD_MATRIX`, matrix position, right/up vectors), so **do not blindly port `p4_ptank_matrix`** or claim rain absent. Confirm 04/12 and 04/15 on hardware, umbrella overlay separate.
- **Umbrella MatFX / alpha late:** upstream b269 has `p4_matfx_env`, b251 `p4_translucent_late`; these named paths **were not found** in current perf06 `rwsky.c`. Could affect transparent canopy and env sheen, but P4P may implement another rule; compare actual geometry/material before claiming missing canopy.
- **Margaret battle TV noise animation:** upstream b225 open issue in `BTL_BOSS_20D`; potential material UV animation / CLUT frame issue. **Not observed/proven in perf06 user tests**; track as a low-priority regression checkpoint, not an urgent fix.
- **b383 floor patch / b386 fusion cards** remain **two separate scoped b388 fixes**: current P4P [`im3d_draw` L11218–11235](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L11218-L11235) culls only Shuffle scoped cards, not all Im3D cullmode2; current `bind_depth` lacks b383 material-only back-face rule. These two are much narrower than an entire renderer transplant. Test cards and Igor table separately before combining.
- **Title return flashes** retain separate first 3 displayed frames / framebuffer bank and mask investigation; `port/video_game.c` restores the previous displayed buffer before [`p4_video_renderer_end` L11373+](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L11373) chooses next backbuffer without clearing both; a conditional stale image hypothesis. Title has historic [2D GE cost comment ~36ms a frame](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L2917-L2920) from b146; **not new perf06 benchmark**.
- **Teddie intermittently green portrait:** cannot ascribe to CLUT without logging. Distinguish sprite resource load/adoption, palette and originalPixels pointer, texture generation, and masked green fallback. [`census2d hwtex` L2943+](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L2943) can record raster/texel/CLUT pointers but caps draw samples; request **ten repeated cold/warm episodes**.
