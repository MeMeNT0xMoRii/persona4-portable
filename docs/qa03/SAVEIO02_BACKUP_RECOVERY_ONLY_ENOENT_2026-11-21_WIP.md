This is a **separate recovery policy limitation** from SAVE-IO-01 post-rename ambiguous sync.

**Hypothesis and falsifier:** A primary that still exists but is truncated/unreadable can prevent a valid `.bak` from being used; test with disposable primary corrupted/truncated and valid backup. Falsify player-facing impact if retail game-layer serialization/validation already detects and restores backup by another path, or backup semantics intentionally only address missing-primary interruptions. **Do not automatically substitute backup after any read error**: corrupted backup, partial offsets, wrong game versions and unexpected permission errors require explicit policy and validation. Current code does not itself prove save corruption occurs in normal use.

**Minimal reproducible protocol:** Host harness for `open_saved`/size/read with isolated temp directory: (A) primary absent + valid backup (expected fallback), (B) valid primary + backup (primary wins), (C) primary present truncated + valid backup (current size/read path does not switch), (D) unreadable primary + backup (platform-dependent `EACCES`/I/O error), (E) backup absent/corrupt. Confirm expected original PS2 save UI semantics before any native change; on PPSSPP T2 and Go T3 use **disposable** saves only. Include normal save, HOME, `ms0:/` and `ef0:/` as negative controls, compare exact before/after SHA256.

**Cost / risk / rollback:** Low static + host test, medium native save policy change; never overwrite valid original/backup to 'test' recovery. Reject/rollback on false backup promotion, save-slot misreporting, changed PS2 serialized bytes, HOME regression or any unexpected loss. If future recovery is implemented, require explicit file validity proof and user-visible non-destructive fallback; preserve both copies until confirmed.
