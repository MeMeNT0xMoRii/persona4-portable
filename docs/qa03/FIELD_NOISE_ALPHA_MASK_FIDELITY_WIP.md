# QA03 — FieldNoise stub, GE alpha-mask fidelity and multi-pass budget (2026-11-19)

**Scope:** Static verified research only, not a patch. Perf06 game runtime commit `29b0fcfdec70222a4052099b67fb4a11e8d8aff4`, branch `dev/v0.27-perf06`; original PS2-US source pinned to `Raikaru/Persona4-Decompilation@363eab8a966d60a9773b45f330f2344329ec4f0a`; upstream PSP `dreikk91/persona4-psp@b388`. T1 means *implementation condition proven*, **not that a user-visible symptom is explained or fixed**. No game-code edit, build or PPSSPP/PSP-Go test in this pass. Golden screenshots and game assets remain private.

## 1. MAJOR corrective finding: original TV-World FieldNoise composite is explicitly bypassed in perf06

- Original PS2 [`FldNoiseUpdate` **FUN_00185850**](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/unplaced/unplaced_inferred_001853e0.c#L203-L585) is a real rendering task. It constructs **70 tiled quads**, **14 horizontal bands**, **concentric masks** and a **screen-feedback layer**, issuing draw/state callbacks and alpha-mask GS registers.
- **Crucial P4P fact not previously accounted for:** [`port/rwsky.c` L436–438](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L432-L439) replaces it with `int FldNoiseUpdate(void *task) { return 0; }` and comments **"shortcut: omit TV-world noise/vignette; restore when the GE path supports its interpolated alpha mask cheaply."** [b388 `rwsky.c` L61–63](https://github.com/dreikk91/persona4-psp/blob/b388/port/rwsky.c#L59-L64) contains exactly the same intentional stub. This is a **T1 explicit fidelity reduction**, not a theory about a hidden fog parameter.
- **Correction of older QA03 hypothesis:** If the P4P symbol override is linked as intended, the *original* `FldNoiseUpdate` 7×10 grid / 14 bands **cannot be the direct source of active black dungeon line artefacts** because its body does not execute. Prior statements about comparing black-line spacing to 19.43 px *as first suspect* are superseded. Retain a cautious caveat until a symbol/map/active-call trace verifies the actual EBOOT hook. Other engine fog (`p4_fog`), geometric shadows, 2D overlays, 16-bit depth / overlay decals and guard clipping **remain possible independent sources**.
- **Priority:** Screen-locked vs world-locked black lines remain worth classifying, but **do not spend a test cycle searching for FieldNoise tile seams in a port where this compositor is disabled**. Investigate `bind_depth` and `p4_decal_bias`, `p4_guard_clip` (including allocation failure), alpha/feedback and scene sector geometry first. FldNoise restoration is a separate later optional original-PS2-Vanilla fidelity feature, **not** an automatic fix for those lines.
- **Order constraint:** Restoring this multi-pass effect **before** the new P0 GE command-list capacity investigation is unsafe: perf06 has just two 65,536-word GE lists and no unified capacity guard; the restored 70+14+ring+feedback layer can increase draw/list load and framebuffer traffic. Even if a renderer supports it, measure fidelity and **GE fill/CPU** on PSP Go; retain rollback if the effect reduces playability. Golden may style the scene differently from Vanilla.

## 2. Separate alpha-mask gap: upstream b253 supports generic 2D per-pixel alpha via stencil bits

- Current P4P [`rwsky.c` L892–901](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L890-L902) defaults `p4_alpha_write_test=1`, `p4_dst_alpha_passes=0`, `p4_alpha_pixel=0`; there is **no `p4_2d_alpha_masks`** setting or equivalent generic branch in this file.
- **Important nuance:** perf06 is **NOT completely missing per-pixel masks**. [`p4_effect_mask=1` and `draw_effect_mask` L3019 / L3260–3355](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3260-L3355) already emulate bit-plane alpha for a **narrow 2D effect state `sky_state[3]==0x31001`**, with a zero-alpha clear and per-bit stencil replacements for suitable nonoverlapping quads. For non-quad/overlapping geometry the path may use coarse alpha steps (not guaranteed exact). `flat_effect_alpha` returns a cheaper constant-alpha path only for known fully opaque, power-of-two swizzled images with uniform vertex alpha.
- **Outside these special states**, [`draw_body` L3495–3553](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L3495-L3553) uses a single stencil reference derived from a vertex and sometimes `p4_alpha_write_test` to approximate texture cutouts; it intentionally **skips some sub-half-screen destination-alpha writer/readers** when `p4_dst_alpha_passes=0`. Neither is equivalent to storing arbitrary textured/interpolated alpha in the frame buffer.
- In b388 [`rwsky.c` L581/L599](https://github.com/dreikk91/persona4-psp/blob/b388/port/rwsky.c#L579-L600), `p4_dst_alpha_passes=1` and `p4_2d_alpha_masks=1`. Its [`port/alpha_mask.h`](https://github.com/dreikk91/persona4-psp/blob/b388/port/alpha_mask.h) supports **restricted 2D alpha-only main-screen passes** (depth write off; DATE off; compatible alpha test), and encodes texture/interpolated alpha by clear + up to **eight per-bit stencil draws per eligible triangle/convex quad**. This is a **T1 capability difference**, not a zero-cost portable solution.
- The [upstream `docs/alpha_rendering.md`](https://github.com/dreikk91/persona4-psp/blob/b388/docs/alpha_rendering.md) documents a critical b251/b252 misconception: **the PSP GE alpha channel is stencil**, not ordinary GL-like fragment alpha. Disabling stencil doesn't magically write per-fragment alpha. They observed a *blank selected System → Title row* on real PSP when masks/readers were incoherent; b253 restored stencil-REPLACE semantics and generic bit encoding. The same report calls b253 **experimental pending more scene validation**.
- **Potential affected P4P visual classes:** masked level-up Persona portraits, System→Title selection label, original dream/TV effects, soft glow and some scene cutout overlays. Apsaras/Zio orbs, original All-Out cut-in clipping, Weather News title and Teddie green bubble are **not proven** to use a relevant alpha writer and must not be relabeled confirmed.
- **Performance risk is substantive:** one eligible previously 1-draw alpha mask might become 1+8 draws, and affected pixel fills can be repeated. With the **unbounded GE list and possible fog >65,536 words**, wholesale enablement could worsen overflow risk even before its frame-time cost is measured. On PSP Go, alpha quality and CPU/GE latency must be measured *together*. Do not toggle `p4_alpha_pixel=1`, which upstream itself found incorrect for true hardware fragment-alpha writes.

## 3. Proven existing fusion checkpoint only samples one phase

- Current [`port/rwsky.c` `p4_fusion_visual_sample` L628–636](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L628-L636) measures eight late dialogue ticks (13–20), and reports RGB pixels and `masks/feedback/additive/meshes` in [`report_fusion_visual` L639–651](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L639-L651). It is *only armed* when the [`tools/psp_census.py` hook L131–136](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/tools/psp_census.py#L125-L139) sees fusion **`state==0x0D && f1==0xCA`** during the acquisition dialogue. Thus it does **not automatically capture** the earlier Apsaras rendering or every frame of Zio/Satan glow.
- The existing instrument is useful **only for that exact acquisition-dialogue checkpoint**. For a true two-consecutive-frame Apsaras flicker, collect effect scene/render dispatch and framebuffer bank alpha during actual visible brightness alternation; do not claim stability from eight dialogue-only samples or confuse frame clocks with effect ticks. Upstream Satan/new-Persona `0x58` evidence is independent of user's particular Apsaras reproduction.

## 4. Reference path for source semantics, NOT a PSP port

Public pinned PC/OpenGL source [`Raikaru/Izanagi@bfb12b6896955b626cc45254c92e8b76789ae147` `docs/renderer_port.md`](https://github.com/Raikaru/Izanagi/blob/bfb12b6896955b626cc45254c92e8b76789ae147/docs/renderer_port.md) maps the PS2 sky2 device `RwDevice`, raster create/destroy, camera begin/end/clear, Im2D and Im3D entry points and GS blend/TEST state. Its [`src/render/p4gl_mdleffect.c`](https://github.com/Raikaru/Izanagi/blob/bfb12b6896955b626cc45254c92e8b76789ae147/src/render/p4gl_mdleffect.c) identifies the original GS packet emitters explicitly: `mdlEffectEmitMaskedTagPair` **0x00489F80** sets framebuffer **alpha-only FBMSK 0x00FFFFFF**, `mdlEffectEmitTagPair` **0x0048A000** restores, `FldNoiseEmitTagged` **0x001852F0** sets **color-only FBMSK 0xFF000000**, `FldNoiseEmitPlain` **0x00185370** restores; `mdlEffectEmitValuePacket` / `SlotPacket` override/restore texture CLAMP. `src/render/p4gl_state.c` models GS alpha blending more directly via OpenGL `glBlendFuncSeparate`. **GL writes fragment alpha natively; PSP GE does not**: this is a valuable *state/owner reference*, **not a transplantable shader or tested PSP solution**.

## 5. Exact isolated test ladder, still pending implementation permission

1. **Safety first:** GE-list pointer/end and per-frame high-water instrument/protect, test in PPSSPP/host before any extra multi-pass rendering; do not generate more commands on the unprotected 64Kiword-list build. Save original binaries/hashes.

3. **Alpha mask validation:** same scene and animation step for System→Title selected text, level-up Persona portrait, dream screen-copy puff, fusion acquired Persona, Apsaras, Zio; record masked writer texture/vertex alpha/GS test, destination-alpha reader, stencil state, mask bbox, number of GE draws/list words, p50/p95 and real Go visual. Keep original `p4_effect_mask` branch where already correct.
4. **Only after performance proof:** consider optional FldNoise restoration in an isolated branch, with first frame and two same-camera consecutive frames, performance and memory budget. Never restore it as an alleged fix for black dungeon lines without a draw attribution.
5. **Keep independent:** Junes parallel RTT camera shadow+pre-update clear, Im3D Fusion card / Igor cull, UI-A wheel and UI-B/C/D/F geometry, title framebuffer tear/flash, Teddie palette/resource lifecycle, Compendium Register invalid-cache freeze, enemy reinforcements, HOME/save.

**Bottom line:** The disabled original noise/vignette is a **verified deliberate fidelity omission**. The **exact mechanism and status of current black lines** is unresolved and prior FieldNoise-tile attribution is **superseded**. No root-cause fix was proven in this pass.
