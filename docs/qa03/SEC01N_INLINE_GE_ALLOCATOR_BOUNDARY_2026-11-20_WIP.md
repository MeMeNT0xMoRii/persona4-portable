# SEC-01n — GE inline allocation is an unchecked two-word command plus payload advance (2026-11-20 17:00 CET)

**Priority:** SEC-01 P0. **Evidence:** T1 static perf06 code, NOT observed overflow. **Frozen source:** `MeMeNT0xMoRii/persona4-portable@29b0fcfdec70222a4052099b67fb4a11e8d8aff4`, `port/rwsky.c` L449–457 and L1901–1920. [Pinned allocator](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1901-L1920).

**Specific new boundary contract:** `list_store[2][64*1024]` supplies exactly 65,536 u32 words (262,144 bytes) per bank. In `__wrap_sceGuGetMemory(int size)`, the gated/cached branch rounds requested payload up to four bytes, advances `gu_list->current` by `rounded_size + 8` bytes, and writes two GE jump words at `at[0]`/`at[1]`. There is **no local capacity check, negative-size check, or overflow-safe addition** before these writes. A valid allocator must reserve both 8-byte command header and rounded payload, not merely compare `size` against bank capacity. The ordinary branch delegates to `__real_sceGuGetMemory`; therefore guarding this wrapper branch alone does **not** establish bounds safety for the whole command list. This is a distinct actionable accounting requirement, not evidence that a particular perf06 scene overflowed.

**Cause hypothesis T0:** command/vertex-heavy fog, battle or RTT paths may reach bank end; the wrapper's header or payload can cross into adjacent memory. **Falsifier:** capture max used words, remaining capacity, all branch counts and final GE execution for repeated deterministic heavy scenes; if every branch and direct writer stays in-bounds with margin, reject overflow as the cause of observed freezes.

**Minimal safe diagnostic plan:** In an isolated diagnostic branch only, use bank-indexed `start/end` from known `list_store` addresses; before allocation check `size >= 0`, safe round-up, `remaining >= 8 + rounded` without pointer wrap; record first attempted overrun with frame/scene, requested size, bank, current offset and gate/cache flags. Check ordinary `__real_sceGuGetMemory` and direct `gu_list->current`/sceGu command writers separately; do not silently truncate or return NULL into unprepared callers. Stop draw submission safely on violation; preserve last good frame. Confirm finished-bank retirement before reuse even after 1s watchdog give-up. Collect per-frame high-water and failures with a bounded recorder, no per-primitive synchronous logging. **Negative control:** identical regular perf06 artifacts and same low-complexity title/menu camera must show no new allocations/flicker; then fog/reinforcement/RTT stress. T2 repeatable PPSSPP first, T3 actual PSP Go after verified diagnostic build. Record three matching regular EBOOT/p4data/p4str SHA256 independently from debug build.

**Risks/cost:** low static inspection; medium instrumented code/build and T2; high GE stall/bank-lifetime regression on hardware. Increasing banks without checking PSP Go free RAM may worsen memory pressure. **Rollback gate:** any rendering regression, memory headroom failure, GE stall, unexpected HOME/save behavior, or unmatched artifact hashes restores immutable perf06. No runtime changes or benchmarks in this pass.
