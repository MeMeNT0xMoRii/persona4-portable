- [L63–82](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_release.py#L63-L82) checks **23 `*.json` movie manifests by count**, not independently against the original ISO's exact movie identity set; it selects their declared `.p4v/.pcm` outputs and the audio manifest. Count 23 alone cannot prove the correct distinct movie IDs.
- [L84–117](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_release.py#L84-L117) overwrites planned files in an existing `UPDATE/PSP/GAME/P4`, records hashes and bytes for **planned** names only, but never removes/rejects existing files absent from `planned`. It tells users to copy the entire UPDATE tree. `DIST` also retains untouched old contents between release packaging passes.
- **T1 consequence:** An old VIDEO or SOUND payload may remain on disk, be copied with the UPDATE, and not appear in current `release.json.files` or its declared `bytes`. ## QA11-B — GE serial/non-pipeline completion remains a distinct fallback safety gate

- Frozen [`port/rwsky.c` L1532–1560](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1532-L1560) takes `pipe=0` branch, calls `sceGuFinish` and, outside `P4_GE_DUMP`, calls `sceGuSync(GU_SYNC_FINISH, GU_SYNC_WHAT_DONE)` **without testing the returned status**. Later [L1607–1620](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1607-L1620) selects `list_store[0]` again. A successful synchronous wait is the **required precondition** for safe reuse; the current routine doesn't explicitly reject a negative/unexpected wait result. That is a **T1 conditional contract gap**, not proof that an error return occurs or that an actual GE list is overwritten.
- The pipelined >1s watchdog/2-bank reuse and false display ACK are already addressed by QA10 and SEC-01r; do not mistake this separate serial-branch check for a new observed freeze. The official [PSPSDK `sceGuSync` reference](https://pspdev.github.io/pspsdk/group__GU.html) describes waiting for a display list but documents its return as **unknown**; inspect exact pinned SDK implementation and actual status semantics before defining an error predicate. Do not add infinite spin, automatic reuse or a silent `pipe=0` fallback without GE completion.
- **Codex falsifier/test:** in an isolated host seam, inject normal completion, explicit error, delayed/never-finished GE and no-frame tick into `pipe=0` path; show a bank/vertex scratch generation cannot be reclaimed on unexpected return. In PPSSPP, measure normal serial `sceGuSync` result and GE retirement, plus fog battle/Junes F009_004 vs school F006_002 negative scene. No T2/T3 result yet.

## QA11-C — Diagnostic recorder and PSP filesystem assumptions

- Frozen [`port/main.c` L61–110](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/main.c#L61-L110) ignores the return values from individual `sceIoWrite` calls and advances text-log tail afterward; the D1 recorder **must not inherit** that loss behavior (previous QA06 finding).
- Existing text-log writer uses a **16KiB thread stack** [`main.c` L113–132](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/main.c#L113-L132). A separate D1 worker is additional thread stack/kernel/heap overhead, not included in the provisional 64KiB D1 data allocation. Respect QA08 fixed `.bss` placement hazard and try checked postboot allocation.
- Public [PSPSDK File IO](https://pspdev.github.io/pspsdk/group__FileIO.html) lists `sceIoRename` and `sceIoSync`, but the latter has an undocumented `unk` argument in the public API. Do not assume that rename+sync gives a proven crash-durable on-device transaction. First verify exact pinned SDK implementation and PSP Go `ef0:/` vs `ms0:/` semantics with post-reopen CRC + injected short-write/disk-full/failed-close tests. Distinguish writer ACK from actual persistent confirmed bytes. D1 0..127 partial POST handling and no per-frame synchronous I/O remain mandatory, with **no new full integration or PSP test yet**.
