## Track 1 — P0 GE interleaving: three independently observable invariants

Actual frozen [`port/rwsky.c` L650–665](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L650-L665): flip worker copies `flip_seq`, tests `ge_finished>=seq`, reads `flip_fb`, waits vblank, calls `sceDisplaySetFrameBuf`, then sets `shown_seq=seq` **regardless of negative return**. Only the FPS overlay counts success; the bank/next-frame gate trusts the unconditional `shown_seq`. Frozen main renderer [L1498–1525](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1498-L1525) waits on previous shown sequence; after 250ms watchdog forces stall update and after 1s **proceeds** despite no certified GE retirement. Frozen [L1587–1606](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1587-L1606) publishes new `flip_fb` then `flip_seq`, toggles `pipe_set` and selects another of two GE list banks. Publication by two independent volatile variables is **not** an atomic `{seq,fb,bank}` record or a hardware fence.

**H0 new executed bounded breadth-first scheduler model:** maximum **3 submissions**, 7 modeled actions (`submit/finish/read_seq/read_fb/present_ok/present_fail/watchdog`), depth<=11 and max100,000 nodes; **188 unique reachable baseline model states**, no node cap hit; **12 unique safe-*candidate* states**, no node cap hit. The baseline modeled traces found 3 *possible* invariant breaches:
1. **Rejected display falsely ACKed:** `submit → finish → read_seq → read_fb → present_fail`. Counterexample from literal `shown_seq=seq` after negative display result; need only a negative PSP API return for reality. **T1 source property**, not user-observed failed API.
2. **Unretired GE bank reused:** `submit → watchdog → submit → watchdog → submit`. With two banks, a second timeout can select bank0 while its earlier GE work still has no retire event. **T1 conditional possibility**; source logic doesn't guarantee actual PSP repeats/reads the bank in this abstract order.
3. **Torn sequence-buffer:** `submit → finish → read_seq → watchdog → submit → read_fb`. Flip worker snapshots earlier sequence, renderer may publish newer buffer after timeout, worker reads it independently. **T1 conditional interleaving**, not an observed PSP GPU fault.

The **candidate safe protocol** in this model rejects reusing an unretired bank, never credits display failure as accepted present, and takes frame buffer from the same committed immutable record as its sequence; 14/14 H0 fixture assertions passed, candidate model reports no safety failure in 12 depth-bounded abstract states. **It has NOT solved liveness:** if display continues failing or GE never retires, safe policy *deliberately quarantines progress* rather than continuing into corrupt GE memory. A real implementation must additionally define retry/timeout/diagnostic export/controlled abort with safe hardware behavior. The model abstracts away PRX scheduling priorities, interrupts, memory-barrier ordering, event flag wakes, exact PSP framebuffer/GE command timing, queue capacity, list ID recycling and 32-bit sequence wrap, and cannot prove a compiled fix. **No claim of exhaustive PSP concurrency proof.**

**Mandatory Saturday SEC-01 acceptance:** one immutable `{seq,fb,submit_bank,generation,list_id}` record published coherently, correct callback GE finish/retirement for that **generation** (not just a reusable list ID), positive display return before accepted-present seq and bank/gate ACK, no bank reuse after 250ms kick or 1s timeout without a real GPU fence, and independent lost-wake/error tests. All direct inlined SDK GE writers still require atomic full-capacity reserve beyond this model. Show host negative/positive interleavings followed by PPSSPP T2; no PSP Go promotion on an unproven list-lifetime fix.

## Track 2 — B0/B2 link-stage actual source owner / no-op patch risk

Frozen manual [`tools/psp_link.py` L124–162](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_link.py#L124-L162) globs **all build/obj/*.o**, compiles port shims then changes some original game objects **in place** with `psp-objcopy.exe --weaken-symbol`; repeated/surviving objects may not match a fresh decomp checkout. The final linker [L202–214](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_link.py#L202-L214) supplies native port objects, stubs and reassembled code first, then all original objects via `objects.rsp`, with `--allow-multiple-definition`. It prints psp-nm final addresses and checks fixed data-image start but **does not produce an ld `-Map` owner report by default**. The release [`tools/psp_hw_debug.py` L48–121](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_hw_debug.py#L48-L121) stages same original objects and relinks a separate PRX profile with its own SDK linker script; **do NOT infer the release owner from an earlier manual EBOOT map**. Thus successful `gcc`/link alone does not prove a modified source function runs.

The new **read-only** [QA10 nm+GNU ld map gate](host_tests/qa10_elf_symbol_owner_gate.py) accepts local `psp-nm.exe` final ELF text, `psp-nm.exe -A --defined-only` original and port object text, and **actual** matching GNU ld link map, plus `--expect FUNCTION=owner.o`; checks that final function exists at one address, desired object defines it, no conflicting *strong* object definitions are silently tolerated, and placed `.text` section range is actually owned by the expected object. It rejects wrong map source and double strong definitions; **missing map / unparsed map address / final disassembly attestation = INCONCLUSIVE exit 3, not fabricated PASS**. **Known limitations:** parser supports simple GNU ld `.text` sections and nm formats, not guaranteed every real PSPDEV format or linker archive extraction; object basename collisions are explicitly rejected; full 40-digit native source SHA, `nm` local/hidden aliases, weak symbol rules, object relocation and dynamic `-ffunction-sections` can require manual inspection. Even a matching map does **not** prove runtime code changed. Real source/object/disassembly identity requires `psp-objdump.exe -dr` and matching final ELF function, build-specific source hash and actual owner/ABI; manual report blocker if not provable.

**Practical extra `-Map` instruction (Codex authorizes on isolated new builder only):** for **EACH actual profile link command**, add `-Wl,-Map,<profile-staging>/p4.map` or appropriate `-Wl,-Map=...` with correct quoting/Windows path syntax. Export, from the same linked profile inputs, `psp-nm.exe -an p4.elf > final.nm`, `psp-nm.exe -A --defined-only <all relevant staged .o> > owners.nm` (large object lists may require batching), and `psp-objdump.exe -dr p4.elf > final.disasm`; never rewrite original `build/obj` or alter immutable perf06 to obtain these. Run the QA10 tool against the **actual single profile**, then compare intended function disassembly/provenance and independently run QA07 PBP/PRX/content manifest guard. **Real positive Windows linker input NOT RUN.**
