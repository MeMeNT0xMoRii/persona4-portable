## New static evidence: bypasses beyond sceGuGetMemory

The pinned perf06 renderer has `list_store[2][64*1024]` words [L458–464](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L458-L464), two **65,536-word/262,144-byte** command buffers in ordinary main RAM. Its wrapper `__wrap_sceGuGetMemory` [L1904–1917](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1904-L1917) advances `gu_list->current` by **8 bytes of GE jump headers plus aligned vertex payload** when the wrapper path is active, without any capacity comparison. The alternate `__real_sceGuGetMemory` branch also needs libpspgu-level instrumentation. A guard **only** in this wrapper is insufficient: manual direct-list writes and library GU command emission bypass it.

**Additional conditional failure mode, newly isolated:** With `p4_list_cached=1` (the default), `__wrap_sceGeListUpdateStallAddr` [L675–711](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L675-L711) flushes cache lines *only if* the stall's computed `to` address is `<= list_hi` (fixed at `list start + sizeof list_store[0]`). If a previous unchecked writer advances `current` beyond that boundary, a later stall update can take the **no-writeback branch** and still call `__real_sceGeListUpdateStallAddr`. This creates a second possible failure beyond RAM out-of-bounds: **GE may consume bytes that have not been published from CPU cache**. This is a **conditional T1 source mechanism**, not evidence that a real perf06 game frame overran the list. The overflow would have occurred already, so improving writeback alone is NOT an adequate safety fix.

**Metric caveat:** The existing conditional `P4_FRAME_TIMING` code computes `timing_bytes` [L1482–1487](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1482-L1487) **before** optional `fps_draw()` [L1490](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/rwsky.c#L1490); it therefore is not guaranteed to be the final list occupancy. The default compile route also lacks timing macros (BUILD-02). `P4_HW_PROFILE` wall-time peaks and `pipe_peak_v/i` are not GE list-word high-water. Prefer address-based word counts using `uintptr_t`, sampled before every capacity-sensitive write and after final GU commands; avoid C pointer-subtraction on pointers already outside an array.

## Outside-port comparison and boundaries

`dreikk91/persona4-psp@b388` [list_room L319–327](https://github.com/dreikk91/persona4-psp/blob/b388/port/rwsky.c#L319-L327) checks `LIST_WORDS-LIST_RESERVE` (**131,072 words/list, 4,096-word reserve**); [L1225–1235](https://github.com/dreikk91/persona4-psp/blob/b388/port/rwsky.c#L1225-L1235) logs list high-water. Upstream's documented fog peak **67,927 words** exceeds perf06's 65,536 cap, but upstream's scene, cache modes, GE command generation and build are not identical to P4P; do not declare perf06 overflow merely from that number. Upstream `list_room` protects selected draw sites; it is not by itself a proof all GU writers are bounded. PS2's original GS path does not share PSP GE buffer allocation, so the pertinent comparison is P4P native PSP vs upstream native PSP.
