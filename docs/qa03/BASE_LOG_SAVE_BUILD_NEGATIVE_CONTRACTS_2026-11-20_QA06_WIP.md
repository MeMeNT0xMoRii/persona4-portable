# QA06 — RESONANCE01 negative contracts: log durability, per-install save path and staged object origin (20 Nov 2026)

**Type:** direct static T1 source audit, original P4P runtime frozen `MeMeNT0xMoRii/persona4-portable@29b0fcfdec70222a4052099b67fb4a11e8d8aff4`. No game-code changes, recompile, PPSSPP run or PSP-Go execution. **This report establishes specific possible failure behavior from source, not that a user actually lost logs/saves or got a stale object.** These are important Saturday validation contracts that were not explicitly separated in the masterprompt before this audit.

## BASE-LOG: existing text logger ACKs bytes even if storage did not accept them (T1)

Source [`port/main.c` L48–111](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/main.c#L48-L111):

- `log_commit` has `void` return. It opens `p4.log` with PSP append; if `sceIoOpen < 0` it silently does nothing. For successful open it calls `sceIoWrite` once for each segment with **no short/zero/negative-write check**, then `sceIoClose` with no result check.
- `log_drain` captures the ring range, calls `log_commit`, then does **`log_tail = head` unconditionally**, regardless of whether the file opened, any write was short/failed, or close failed. `log_dropped` also resets before its own blind `log_commit`. Consequently a disk/ef0:/ms0: failure may silently lose queued records rather than keep them for retry.
- `p4_fusion_trace` L75–83 directly calls synchronous `log_commit` for selected checkpoints. It can both fail silently and impose a device open/write/close stall; it is not a safe per-frame/per-candidate telemetry strategy. Existing ring worker sleeps 100ms L113–121 and is useful for *cadence/worker scheduling*, not as an acknowledged reliable binary storage protocol.
- This is not proof of an actual lost user's log, because no failed write was observed in this research pass. New D1 binary recorder **must use its own ring, error-returning full-write loop, CRC/header integrity, explicit commit/rename/verify/ACK**; never inherit `log_drain`'s advance-on-attempt behavior. Test open failure, short write, zero write, negative write, interrupted temporary file, close/sync/rename failure, disk-full, rapid HOME, sticky SEALED incident. Allow `p4.log` to remain best-effort; mark it as lossy in failure reporting unless Codex separately fixes text logger with performance tests.

## BASE-SAVE: same logical profile in a different install folder uses a different save location (T1)

Sources [`port/paths.c` L14–41](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/paths.c#L14-L41) and [`port/memcard.c` L16–23, L77–87](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/port/memcard.c#L16-L23):

- `p4_paths_init` derives `p4_game_dir` from the executable's actual `ms0:/...` or `ef0:/...` folder and assigns `p4_save_dir = p4_game_dir + "saves"`. `memcard` appends `/card0` or `/card1`. Thus **separate installed P4-RESONANCE01-Regular and P4-RESONANCE01-Diag folders do not share saves by default**, even if both EBOOTs run the same game scenario. All game containers/index/SOUND paths are likewise relative to `p4_game_dir`; a bare EBOOT in an empty per-profile directory does not have the needed assets.
- `memcard.c` L102–110 reads `.bak` if the primary is missing and L146–188 writes `.tmp`, tries save sync/rename into `.bak`, then final sync. This preserves one previous copy under normal success/error conditions but does not make a user's original edit/save clone safe for repeated experimental runs. Keep original saves off-device or immutable offline; use **separate, hash-verified private cloned test cohorts** original/minimal/heavy, and restore an identical copy before each A/B leg.
- **Storage tradeoff:** completely separate test folders may duplicate large game container files; no assumption that the device has enough free space. Safer bounded procedure if insufficient free space: retain untouched perf06 backup on PC, stage one isolated `P4TEST` install with the required unchanged private containers/audio/video, atomically replace the **verified matched package triplet** EBOOT/p4data/p4str between profiles only while game is fully closed, restore the same cloned `saves/card0|card1` cohort before each test; maintain manifests and no simultaneous mixed versions. This is a proposed test procedure, not a proven PSP atomic install script. Never write into original perf06 install or private original save.
- A/B comparisons lacking the **same save clone SHA, scene/camera, exact profile artifact triplet and cold/fresh process** cannot isolate an engine regression. RTT sticky state also requires a fresh launch after changes.

## BUILD-02: link modifies object symbol strength before the diagnostic build consumes the objects (T1)

Sources [`tools/psp_census.py::shim/check` L692–765](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_census.py#L692-L765), [`tools/psp_link.py` L124–145, L192–229](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_link.py#L124-L229), and [`tools/psp_hw_debug.py` L25–70, L95–163](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/29b0fcfdec70222a4052099b67fb4a11e8d8aff4/tools/psp_hw_debug.py#L25-L163):

- The census mirrors the exact pinned PS2 source and applies string-anchor FIXES/ASM_FIXES; a changed original source or missing match should fail the anchor `assert old in text`, not be hidden with a broad replacement.
- `psp_link.py` compiles native `port/*.c`, determines port-owned symbols and runs `psp-objcopy.exe --weaken-symbol=<name>` **against existing generated game `build/obj/*.o`** before linking (L140–145). Its linker also uses `-Wl,--allow-multiple-definition` L206–208. Reusing old object directories can therefore build a binary that links but does not contain the intended new game-source shim or silently picks the wrong duplicate definition.
- `psp_hw_debug.py --release` copies the then-existing `build/obj` objects into an isolated stage, compiles fresh port modules, two-pass links digest-embedded data, validates expected PRX image address/imports and writes `manifest.json`. It **does not itself regenerate changed original C objects**. The base `p4str.bin` equality check is useful but cannot prove every changed function is present or reachable.
- **Saturday requirements:** clean isolated source checkout, verify exact decomp and PSPSDK/source/toolchain commits, run `psp_census.py --compile` **after** every source-FIXES/game-C shim change, require failed_compile empty, run address/pointer/audit, link, inspect actual ELF symbol owner/map/disassembly of each changed function and check newly invoked functions against `missing.txt`/`stubs.c` and reasm refusal. Rebuild artifacts with new manifest, verify `p4.elf`, `p4.prx`, EBOOT, p4data and p4str hashes. Reject any pass with stale objects or unresolved new code despite apparently successful linker exit. Preserve original environment and baseline. Prevent filename/shared data folder mix-ups.
