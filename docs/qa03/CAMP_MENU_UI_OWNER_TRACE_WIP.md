## 2. New architectural points for targeted menu QA

- **Skill list:** `cmpSkillMenuDraw` only adds scrollbar thumb offset divided by `skillCount - 6` when `skillCount - 6 > 0` [L640–660](https://github.com/Raikaru/Persona4-Decompilation/blob/363eab8a966d60a9773b45f330f2344329ec4f0a/src/Camp/cmpSkill.c#L640-L662). **No division-by-zero in that guarded expression**; don't invent a skill menu crash there. The skill icon and text row are produced separately from `sdkSpriteDrawSized` and `datEntryDrawByKind`; if text/icons are misaligned, inspect those source-relative offsets before changing the entire table.
- **Equip vs Persona rows:** both use 33-source-unit party-row pitch, but their base X differs, **35 vs 82**, and the actual Persona view includes its own model-effects path. A combined global offset would alter differently aligned pages. Character level/stats differences (#27/#31/#36/#38/#41) reflect distinct save states, not proven data loss.
- **Persona/Status negative control:** #38 Status portrait and left panel look broadly aligned. Persona #36 may use different Art/animations and animated model. Don't apply the Social Link portrait adjustment to Persona status or main character status pages without tracing their actual child tasks.
- **Text and footer:** all three Camp menus use `sdkSpriteDrawFooter` and font/entry draws separately from their principal panels. A footer-button crop or readability problem must be measured as **its own shared footer draw class** with at least Skill, Equip, Persona, Config and one shop screenshot as witnesses, not solved by changing whole-screen projection. Visual content in Golden vs P4P (e.g., Persona level, menu item names, equipment, unlocks) is not a geometry signal.
- **Crossover with GE alpha and command lists:** 2D menu text may depend on destination-alpha stencil/reader pairing. Reproducing a missing System→Title row in perf06 needs its exact alpha-writer + small-feedback reader; b388's generic 2D mask support could take up to eight more passes. **P0 64Kiword GE-list preflight still precedes visual draw amplification**.
