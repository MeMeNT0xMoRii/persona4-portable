## Four tools, not one expensive always-on recorder

| Diagnostic | Best for | Does NOT prove | Overhead and safe gate |
| --- | --- | --- | --- |
| **A. External PPSSPP WebSocket debug adapter** | Read-only CPU thread/semaphore/backtrace, game state, GPU list disassembly, framebuffer/color/depth/stencil screenshot and one GE recording. Run software accuracy backend and host GPU backend separately. | Hardware-real time, PSP Go memory races, hardware-only IO, real crash persistence. | No added native GE words. Version handshake, very small on-demand dump, private savedata/screen memory, avoid trace floods and non-local debug access. |
| **B. Native PSP Diag-Lite Flight Recorder** | True Go CPU-game tick/GE submission/completion/display accepted/alloc/IO/fusion state, 128 PRE+0..128 POST events, progress classifier. | Universal root cause, survival after process/kernel/power stops before storage commit. | Proposed 512×64B ring (~32KiB), no per-draw disk IO, bounded background writer; actual PSP code/ABI and perf overhead not yet built. Must handle zero POST/hard stall and tested final file verify. |
| **C. Targeted one-shot native UI/RTT probes** | Exactly one sprite owner/record, source XY+native hull/scissor; 128×128 shadow target/projection, texture/CLUT cache generation and effect alpha. | Every screen/animation or all renderer paths. | Build-time OFF by default, one timestamped bounded event per *state transition*, not per vertex; only after SEC-01 full list capacity/retirement. |
| **D. Host deterministic tests + PSPLink development-only** | Compile generated source ownership, synthetic GU ring bounds, geometric math, negative IO, packet-list cycles; optional physical GE/ram state via PSPLink when safe. | A host test passing means safe hardware. PSPLink may halt/perturb graphics and needs an actual connected/dev PSP. | No game source edit for pure host; dev-only host0: rescue outside renderer, never user beta default; don't perform excessive PSP savemem or GE readbacks under a live in-flight bank. |

## 2026-10 PPSSPP software GE-specific investigation discipline

Authoritative external study: [PPSSPP 2026 bit-exact GE write-up](https://www.ppsspp.org/news/ge-bit-exact/) and [raster arithmetic/coverage](https://www.ppsspp.org/docs/psp-hardware/gpu/raster-pipeline/), summarized in [cross-port report](CROSSPORT_PSP_2026_GE_SOFTWARE_SHADOW_CACHE_AND_TIMING_QA06_WIP.md). Software GE reproduces many PSP pixels bit-exact but has remaining known self-texture and depth-swizzle limitations, so classify screenshot diff **software renderer vs host graphics renderer vs real Go**; do not assert all emulated pixel differences are port bugs. PPSPP software mode cannot be used as a Go FPS estimate.

**Stop conditions:** if GE bank lifetime unsafe, no additional debug draw/RTT pass; if hard freeze kills worker, no claim a RAM incident file exists; if one sprite title differs only from Golden exclusive style, leave Vanilla regular unchanged; if host record/screenshot has copyrighted game pixels, keep it private; if compilation source or artifact not actually linked/tested, mark NOT BUILT/NOT RUN rather than spending credits on vague code modifications. Prefer one precise 1-frame diagnostic + 1 negative control to 100 always-on printfs; keep existing perf06 p4.log only best-effort.
