# QA03 — preserve PS2 visual quality while approaching 20→30 FPS on real PSP Go

**Source audit, 2026-11-19.** T1 = source verified; T0 = untested proposal; T2 PPSSPP verified; T3 real PSP Go verified. No new EBOOT, timed hardware run or change to game code. Relevant areas include School Corridor, Shopping North/Central, Junes West, Samegawa Riverbed, dungeons, Velvet Room, battles/fusion, indoor scenes and intro. User targets **constant ≥20 FPS first** (50 ms per presented frame), then **near 30 FPS** (33.33 ms/frame), without blind PS2 visual downgrades.

## 1. External actual PSP port techniques — separate what can transfer from what cannot

**OpenUG2-PSP** https://github.com/jussimir-labs/OpenUG2-PSP, native beta v0.4.0 README and KNOWN_ISSUES both explicitly **do not certify global stable 30 FPS**, all models or finished full career. It is therefore a valuable engineering reference, **not a proof our P4P target can already run 30 FPS**.

## 2. Verified current P4P renderer baseline (do NOT reimplement defaults)

**Pinned runtime file:** https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c (retail P4P build baseline 29b0fcfd...; source blob documented separately).

- L1022–1028: **p4_swizzle_textures=1** already keeps native raster textures in PSP 16-byte by 8-row cache-friendly blocks; not a new toggle.
- L1091–1109: **p4_mip_build=1, p4_mipmaps=1, p4_mip_min=64** already generate palette-index mip chains on PSP; generated with 2:1 point decimation, which can cause aliasing/edge noise. Candidate: offline higher-quality palette/alpha-aware mip generation on native original assets, or **scene-specific LOD bias** to retain sharper signs while preserving far texture-cache performance. Requires actual screenshots/fill and memory measurements.
- L863 and L906: **p4_guard_boxes=1, p4_guard_clip=1** already cull off-screen guarded chunks and clip. Internal comment cites ~50→45 ms in a historic room baseline, **NOT a Junes or School hardware result**. Audit guard-box misses, CPU clipping overhead, false-positive/false-negative and allocation fallbacks. No blind disabling of guard in narrow corridors due black holes.
- L889, L910, L915: **p4_uv_memo=1, p4_mesh_cache=1, p4_cache_budget=6MiB** (with a 4MiB minimum and heap reserve). This cache is a main-RAM tradeoff: a poorly chosen bigger cache may increase fragmentation and reduce renderlist headroom, even if mesh builds drop. Measure cache hits/misses and RAM live bytes before changing.
- L794/L9094: **p4_ge_skin=1** already uses GE skin strategy in eligible cases. L804–806: **p4_skin_lod_depth=0** meaning optional far animation/skin LOD is disabled by default, **not already a performance win**. If skin/animation is dominant, consider scoped distant actor LOD with original PS2 animation integrity and 16:9 screenshots; tests for long hair, clothing, motion and battle to avoid visible snapping.
- L458–464 and L1900+: **two 65,536-word GE display lists in main RAM with no unified overflow guard**. This is **P0 safety gate**; b388 reports fog workloads exceeding capacity. No extra masked passes, shadow layers, or aggressive draw increase until capacity and all writers are bound/proven.
- L893–901: default **p4_dst_alpha_passes=0** sacrifices some actual soft effects; enabling can add square overlays. It is not a free way to regain PS2 fidelity. Source-specific stencil writer→reader mask pairing needed.
- L1197–1300, 1403–1430, 3770+: RTT limited by GE eDRAM pool, wrong-target preclear candidate and **perspective-only projection**; known Junes 128×128 silhouette shadow route needs parallel camera, mask/Im3D and clear alignment. Restore correctness before declaring low-resolution images a texture problem.
- Runtime **pipeline=1** and frameskip enabled; serial GE diagnostic invalid as stock FPS comparator. Use frames **presented**, simulation ticks, CPU time, GE wait, p50/p95 time, GE list words/draws and low-overhead timing separately. For steady 20 FPS, examine tail p95/p99 and frame pacing, not average alone.

## 3. Fidelity-first optimization hierarchy

**P0 safety (before new workload):** bound GE display-list writers, 2-buffer alignment/cache flush, quantify max list words/peak RAM and save/HOME. Fix unbounded memory writes and correct camera RTT failure fallback without introducing disappearing geometry.

**P1 restore missing/faulty renderer features correctly:** parallel RTT shadow, target clear, depth/decal z bias, screen alpha writer-reader, texture alpha and scene-specific culling, Apsaras/Thunder/particles, viewport/2D overlays. These are not "higher resolution" settings; erroneous effects can make PS2 art look substantially worse even at the same pixel density.

**P2 isolate cost by source area:** school corridor F006_002, Shopping North F008_001, Junes West F009_004, Riverbed, dream/fog and central shopping scene exact ID to be verified (do **not** assume North=Central). For each: 20 s still + 10 s walk with fixed clock/controller and day/weather/camera, matching original save; first baseline perf06 stock, then isolated instrumentation, repeated A/B/A and real PSP Go. Record CPU transform/animation, 2D/OT, GE wait, present, mesh/vertices, state/texture binds, texture live bytes, RTT passes, alpha writers, guard clipped/discarded, memory and list high-water. **Do not invent FPS metrics for untested scenes.**

**P3 low-risk reuse:** batch static atomic GE state if compatible, eliminate redundant repeated sprite/texture binds, reuse converted vertex/UV data on unchanged geometry, optimize CPU-side per-child menu transforms if profiling shows cost, compact draw commands only after no overflow. Keep UI-A/B/C/D/G independent and reproducible.

**P4 conditional source-aware geometry & texture:** (a) conservative room portal/cell occlusion with source geometry test; (b) static far LOD selected by *screen-projected error*, not fixed aggressive distance; (c) full-resolution foreground/portraits/fonts but lower sample/mip for distant surfaces; (d) offline high-quality index-safe mip generation and swizzle, only if quality/color/alpha measured better; (e) alpha/RTT composite only where original PS2 actually uses it. Scope to scenes, distance and material classification.

**P5 controlled performance/quality dial:** if target unattainable in particular scene, provide real choices with two named profiles only after PSP Go A/B. Default fidelity profile preserves PS2 art/effects; alternate balanced profile changes distant geometry/render resolution selectively, never entire resolution, camera field of view, UI sharpness or masks without clear user option. No dynamic resolution slider for a game that needs pixel-perfect 2D until all targets/scissor/posteffects accept it.

## 4. Measurement and honest goals

- 20 FPS ↔ 50ms per presented frame; 30 FPS ↔ 33.33ms. Frameskip may make simulation run near intended cadence while rendering only every 2nd frame; **report both** and note if late frames cause inconsistent motion/controls.
- Don't report PPSSPP on PC as real PSP Go. Separate PPSSPP GPU software/hardware backend, PSP 3000/Go, clocks and RAM profile. Do not compare b388 vs perf06 without same saved scene/field/weather and scanout identity. Current user reported roughly low-teens instantaneous Junes West samples under both; **these are not new p50/p95 results**.
- Run image regression before FPS acceptance: source PS2 US vs perf06 (Vanilla art), Golden 120 pairs for composition only; same camera/time/animation; inspect black lines, light orbs, Apsaras/Thunder, weather and alpha glows, tree/sky texture seams, all battle wheel and cut-ins.
- **Failure discriminators:** high CPU/low GE wait → skin/OT/tasks/mesh builds; high GE wait/2D pixels → fill/alpha/feedback; many texture binds/cache misses → swizzle/mip/CLUT residency; RTT count >0 and shadow missing → projection, clear and quad routing; stalls during movement → streaming/assets load; visibly missing polygons → guard/cull/far-LOD bug, not "performance feature".

**No PS2-level fidelity or 20/30FPS achievement proven here.** The practical strategy is preserving full-quality source assets wherever screen-visible, fixing fidelity-path errors, then freeing CPU/GE/texture bandwidth with verified *scene-scoped* optimizations.
