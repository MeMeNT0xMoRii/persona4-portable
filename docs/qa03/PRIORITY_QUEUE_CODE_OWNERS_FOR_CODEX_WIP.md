## How to use with Codex/Work and the hourly research run
- Start in exact order: HANDOFF_LIVE.md → this queue → README.md, QA_MATRIX_WIP.md, MASTERPROMPT_WIP.md → narrow linked source report. Check last completed ID, code hash/commit, recent change and unresolved uncertainty. **Do not restart the same repo-wide search**. Check original PS2 source and current PSP caller, not only docs.
- Perform the **highest actionable** P0 safety/reproduction issue first, but **rotate at least one independent subsystem per research run** so UI, rendering, animation, assets, sound/video, field, tasks, input, save, streaming, build and automated playthrough all progress. Prioritize a new exact source fact rather than rewriting historical prose.
- Every new finding must append: ID; source file/function/**exact line range or original retail address**; source commit; actual current P4P adapter/draw path; why linked to an observed symptom; T0 (hypothesis) / T1 (static source) / T2 (repeatable PPSSPP) / T3 (real Go); instrumented scene/save and rollback/test result. "No evidence" stays open. Cite any third-party public URL; never upload game assets, saves or screenshots.
- **QA/Research only until explicit execution approval:** no modifying game source, building a release, PS2/PSP port merge or copying third-party assets. Documentation commits allowed on existing QA branch. Codex runtime passes should use isolated feature branches, one change per A/B, stable commit and fail-fast guards. Handoff is the LAST write of successful research runs.

**New source-verified comparison (NOT measured on P4P):**
- OpenUG2-PSP [tools/convert_pvs.py L1–48](https://github.com/jussimir-labs/OpenUG2-PSP/blob/main/tools/convert_pvs.py#L1-L48): offline conversion of EA's **existing PVS section/zone data** into PSP draw-cell gates; [psp-viewer/world.c L63–94](https://github.com/jussimir-labs/OpenUG2-PSP/blob/main/psp-viewer/world.c#L63-L94) compiles static batches into GE calllists and gates them by visibility, conservatively retaining near geometry. Persona4 has **not** been proved to ship the same precomputed visibility; a **new static room/portal group** would be T0 and requires 16:9 safe/animated scene and depth occlusion checks.
- OpenUG2-PSP [tools/convert_mips.py L1–60](https://github.com/jussimir-labs/OpenUG2-PSP/blob/main/tools/convert_mips.py#L1-L60), [psp-viewer/world.c L634–645](https://github.com/jussimir-labs/OpenUG2-PSP/blob/main/psp-viewer/world.c#L634-L645): offline swizzled T8 mip chains; source comments cite PSP GE 8KiB texture cache and tuned LOD bias -16 for fine signs. P4P **already** enables [p4_swizzle_textures=1 L1025](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1022-L1028) and [p4_mip_build/p4_mipmaps=1 L1095](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L1091-L1109). Best candidate is **profiled texture format/LOD/mip quality and loader cost**, not another swizzle implementation.
- SHAR-PSP [tools/p3dopt/README.md](https://github.com/antoxa2584x/SHAR-PSP/blob/psp-port/tools/p3dopt/README.md): offline palettization reduced **its own** frontend texture memory 24.3→7.4MiB; never project this onto Persona4, whose many GS assets already use palette textures. Its mesh decimator is inappropriate for all character skins/near important buildings without frame-local visual comparisons.
- OpenUG2-PSP [README 0.4.0](https://github.com/jussimir-labs/OpenUG2-PSP) explicitly **does NOT guarantee global stable 30FPS** or full game acceptance. It does demonstrate versioned, user-disc-only local data generator, data+EBOOT hash checks and private bug artifacts. Consider similar reproducible P4P beta builder and opt-in log hotkey, not automatic addition of game assets.
- **New P4P performance constraints:** [port/rwsky.c L863](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L863) guard boxes already on; [L889–915](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L889-L915) UV memo/mesh cache already on (cache budget ~6MiB); [L794–806](https://github.com/MeMeNT0xMoRii/persona4-portable/blob/dev/v0.27-perf06/port/rwsky.c#L794-L806) optional far skin LOD off (depth 0).
